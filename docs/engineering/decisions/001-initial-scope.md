# ADR 001 — 첫 배틀 검증과 임시 규칙

> 초기 의사결정의 과거 기록입니다. 아래 단계 수·제약·미구현 항목은 작성 당시 상태이며 현재 사용 안내가 아닙니다. 현재는 [STATUS](../../STATUS.md), [구조](../ARCHITECTURE.md), [DB](../DATABASE.md)를 따릅니다.

날짜: 2026-10-04. 상태: 엔진 검증 단계에 채택, 제품 규칙은 임시.

## 맥락과 결정

기획만 확장하지 않고 사람이 한 경기를 끝낼 수 있는 작은 결과부터 만든다.
TypeScript + Node.js에서 Showdown을 호출하고, 화면과 DB 없이 CLI로 우선 검증한다.
전투 규칙 전체를 직접 다시 구현하는 대안은 범위와 오류 위험이 커서 선택하지 않았다.
Next.js는 웹 단계에서 추가한다. 별도 NestJS/Spring 서버는 현재 필요하지 않다.

## 실행 중인 임시 규칙

- 9세대 OU를 엔진 검증용 기반으로 사용하고 팀 최대 3마리·레벨 50·테라스탈 금지 규칙을 추가한다.
- 이는 최종 게임에 OU 금지 목록과 대전 규정 전체를 채택한다는 결정이 아니다.
- 고정 6종의 두 팀, 중립 성격, IV 31, 도구 없음, 일반 특성, 공격 기술 4개.
- 노력치는 HP에 1, 나머지 0. 의도적인 미배분임을 Showdown 검증기에 알리는 값이며 능력치는 EV 0과 동일하다.
- 팀 순서는 고정. 플레이어는 기술과 자발 교체를 선택하고 AI는 최대 예상 데미지 공격과 필수 교대를 한다.
- 시드 기본값 [1, 2, 3, 4]. 테스트에서 다른 시드도 검증한다.
- 200턴을 넘으면 검증 실패로 종료한다. 승리나 보상을 주는 규칙이 아니다.
- 특수 기믹은 첫 통합 테스트에서 비활성화. 플레이어가 향후 모두 사용 가능하다는 가정은 유지한다.

Custom Game은 기본적으로 실제 HP를 공개하므로 상대 정보 제한 요구에 맞지 않았다.
표준 공개 HP 비율과 팀 검증이 있는 포맷을 기반으로 전환했다.
최종 혼합 기믹 규칙은 별도 ADR과 실제 경기 검증 후 선정한다.

## 다음 단계의 임시 제안 — 아직 코드 미반영

층 사이 완전 회복, 실제 영입한 종만 해금, 돈은 패배 후 보존,
영입 생략 가능, 첫 구매 기능은 성격 선택권.
가격·지급량·해금 단위·영입 개체 세팅은 아직 정하지 않았다.

## 재검토 시점

웹 한 경기에서 서버 수명·동시 요청을 검증하고,
보상 구현 전에 영구/도전 데이터와 트랜잭션을 결정한다.
네임드 특수 기믹 구현 전 엔진 포맷과 병용 제한을 다시 결정한다.
