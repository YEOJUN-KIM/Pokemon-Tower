# 다음 작업

기준: 2026-10-18. **100층 Normal Mode의 1차 완성**을 목표로 남은 작업만 관리한다. 구현 상태는 [STATUS](../STATUS.md), 완료 내역과 검증 기록은 Git·기존 reports/artifacts에서 확인한다.

대규모 시스템 기반과 중간점검 리팩터링은 완료한 상태로 본다. 앞으로는 **콘텐츠 보강 → 밸런스 → UI/UX 완성도 → 비주얼/연출 → 사운드 → 실제 장기 플레이 검증 → 최종 QA** 순서로 완성도를 높인다. 사람의 100층 플레이는 초기에 기준 Run을 확보하고 각 단계 변경 후에도 반복한다. 새 구조 문제가 발견될 때만 해당 부분을 최소 수정한다.

## 1차 완성 목표

### 콘텐츠

**네임드 NPC 샘플**

- 현재 [6종 파일럿](../gameplay/named-trainer-sample-pilot.md)을 기준으로 필요한 NPC부터 단계적으로 검토한다. 모든 NPC를 당장 5~6마리 후보형으로 전환하지 않는다.
- 기존 팀과 부족한 네임드를 확인하고 포켓몬 조합·기술·지닌 도구·특성·성격·능력 포인트·기믹 담당·에이스·AI tier/ceiling을 함께 검토한다.
- 관장·사천왕·챔피언·빌런의 체감 차이를 확인한다. 기존 Sample/Rank·생성·저장 구조는 유지하고 [NPC 데이터](../engineering/NPC_DATA.md)의 원본/export/검증 경로를 사용한다.

**이벤트 콘텐츠**

- 상자·브리더·여행 상인·도전자·Raid·순간이동·히든상점·로켓단 캠페인·히든보스는 구현된 기반이다. 새 엔진이나 같은 시스템 재구현을 남은 작업으로 잡지 않는다.
- 콘텐츠가 부족한 부분부터 Raid 보스·패턴·보상, 도전자 Sample, 빌런 조직 테마/NPC/보스/보상 차별화를 보강한다. 로켓단 외 조직이나 히든보스 추가는 실제 필요성을 확인해 범위를 정한다.
- 위험 선택 배틀·연승 도전·라이벌·교환 NPC는 1차 완성 필수가 아닌 후순위 아이디어다. [이벤트 후보](../gameplay/EVENT_CANDIDATES.md)에서 관리한다.

### 밸런스

**이벤트 빈도와 기대 가치**

- 공통 발생률 **10%·쿨다운 2**를 출발점으로, 전체 발생 → 종류 weight → 내부 결과 weight를 구분해 측정한다. 기준 위치는 [이벤트 개발](../engineering/EVENT_SYSTEM.md)에 있다.
- Raid 발생 시점/빈도, 빌런 캠페인·도전자·히든상점 빈도, 상자 위험/보상 비율, 이벤트별 기대 가치와 일반 전투 흐름의 끊김을 확인한다.
- 로켓단 초기 weight 100 등 임시 튜닝도 실측 대상으로 포함한다. 자동 테스트 통과만으로 최종 수치를 확정하지 않는다.

**전체 경제·영구재화**

- 일반 전투·이벤트·보스 보상에서 얻는 코인/성장 포인트/티켓/아이템과 일반·히든상점, TM·도구·성장·알·영구 업그레이드 소비를 하나의 흐름으로 측정한다.
- Run별 획득·소비·남은 재화, 코인 사용처 가치, 성장 포인트 희소성, 일반/레어/슈퍼레어 알과 전용 티켓 가치, Master 보상·트레이너 장비·업그레이드 가격을 비교한다.
- 초반 부족과 후반 과잉을 함께 확인한다. 현재 알 등급/이로치 확률·1회 가격은 근거 없이 즉시 바꾸지 않는다. [알 규칙](../gameplay/EGGS.md)을 기준으로 측정 후 조정한다.

**사람의 실제 100층 Run**

- 우선 기본·혼합·대표 기믹 룰 하나로 비교하고, 문제가 드러난 룰/구간부터 확대한다. 자동 테스트·AI 시뮬레이션으로 대체하지 않는다.
- 초/중/후반 난이도, 급격한 층별 상승, 특정 NPC·룰의 과도한 강약, 회복/아이템/재화 부족과 후반 코인 과잉을 기록한다.
- 이벤트 빈도·반복 피로·전체 플레이 시간·50/100층 보스·저장/재접속을 함께 확인한다. 기존 단판 보고서는 참고자료이며 현재 사람의 Run 결과로 취급하지 않는다.

### UI/UX

**조작 체계 통일**

- 배틀·도감·출전 준비·배낭·상점·영구 상점·알·이벤트·NPC/보상 선택·팝업을 PC/모바일에서 직접 조작한다.
- 확인/취소/뒤로 위치, 기본 포커스·방향키·Enter/Space·ESC/Back·기존 Z/X, 팝업 focus trap/복귀, 리스트/스크롤 이동을 확인한다. 현재 모든 화면이 이 입력을 동일 지원한다고 가정하지 않는다.
- hover/keyboard focus/selected/disabled/danger 상태, 마우스와 커서 일치, 터치·클릭 영역·버튼 크기·정보 우선순위·오조작을 점검한다.
- 기존 `game-keyboard.ts`와 공통 dialog/navigation을 재사용한다. 화면별 키보드 시스템을 새로 만들거나 모든 UI를 하나의 컴포넌트로 합치지 않는다.

**컴포넌트·레이아웃 일관성**

- 주요/보조/뒤로/취소/위험 버튼, 카드·패널·탭·리스트·팝업·정보창·상태 표시의 역할과 강조 규칙을 정리한다.
- Selected와 Focused를 구별하고 Disabled/Danger를 일관되게 표현한다. 기능이 다른 화면의 레이아웃은 억지로 같게 만들지 않는다.
- 서버 기능만 있고 화면이 없는 기능(알 기계 조정 등)은 연결 필요성과 범위를 별도로 판단한다. 현재 사용자 화면에서 사용할 수 있는 기능처럼 기록하지 않는다.

**포켓몬 RPG 스타일 비주얼 리디자인**

- 조작과 UI 뼈대 정리 이후 진행한다. 공식 UI 복제 대신 읽기 쉬운 패널·선택 커서·배틀 메뉴·도트 감성·둥근 패널·굵은 테두리·타입 컬러·대화창·탭·간결한 애니메이션의 공통 언어를 검토한다.
- 배틀·도감/상세·출전 준비·배낭·상점·영구 상점·알·이벤트·보상 화면에서 비교한다. 현재 스타일을 이번 문서 작업으로 교체하지 않는다.

### 연출

**기술 VFX**

- [기존 연출 계획](../gameplay/MOVE_EFFECTS_PLAN.md)에 따라 공용 타격·베기·찌르기·구체·빔·파동·불꽃 줄기·폭발·물·전기·얼음·독·상태이상·회복·능력 변화 계열을 우선 보강한다.
- 일반 기술마다 전용 에셋을 만들지 않는다. 대표 전용기·Z기술·특수 기믹·보스의 중요한 장면에 선택적으로 전용 연출을 둔다.
- 크기·발사/타격 위치·타이밍·양쪽 방향·모바일·1×/2×/4×·스킵·동작 감소를 함께 점검한다. 배경/필드 디테일도 기존 계획에서 비교하되 별도 엔진을 만들지 않는다.

**사운드/BGM**

- 기존 `game-audio.ts`·`music-score.ts`를 재사용해 UI 이동/확인/취소·구매·보상·공격/타격·효과/급소·회복/능력 변화·등장/교체/기절·아이템·이벤트 효과음의 역할과 빈 구간을 정리한다.
- 메뉴·일반/네임드/보스/빌런/Raid·이벤트·상점/정비의 곡 선택과 공유 여부를 검토한다. 모든 구간에 별도 BGM이 이미 있다고 가정하지 않는다.
- 음량 균형·루프·화면 전환·곡 전환·효과음 동기화·중첩과 긴 플레이 피로를 확인한다. 음향 시스템을 중복 구현하지 않는다.

### 안정화

**저장·이어하기·개인 실행기 실사용**

- 일반 전투 중/직후·영입·이벤트 선택 전/보상 선택 중·도전자·Raid·빌런·순간이동 후·히든상점에서 종료→재실행→이어하기를 확인한다.
- 50층 이후·90~100층·클리어 직전도 포함한다. 중복 지급/차감 없음, 이벤트와 팀/아이템/보상 snapshot 보존, 정상 다음 층 진행을 검사한다.
- Windows 개인 실행기의 종료/재실행·주소 확인·DB 경로·백업/이전을 실제로 확인한다. 개발 DB와 Docker 볼륨은 구별한다. [저장/실행 기준](../SESSION_HANDOFF.md)을 따른다.

**최종 전체 QA**

- 1차 완성 직전에 신규 기능 추가를 잠시 멈추고 시작→계정→스타터→배틀→영입→육성→상점→이벤트→알→도감→NPC/보스→100층→클리어를 직접 검증한다.
- 진행 불가·포커스·저장·중복 지급·잘못된 문구·화면 깨짐·모바일·4× 메시지 누락·VFX 위치·사운드 중첩·긴 Run의 상태 누적을 정리한다.
- 자동 회귀 검증과 사람의 장기 플레이 결과를 함께 확인한다. 수치 조정/콘텐츠 보강 후 관련 저장 호환도 다시 확인한다.
- 변경한 기능의 STATUS·gameplay·engineering·인계 문서를 함께 갱신한다. ROADMAP에 완료 로그를 쌓지 않는다.

## 1차 완성 이후

- **Hard Mode:** Normal Mode 완성 후 별도 설계한다. 상대 육성/AI tier·이벤트 위험·Raid·보상·자원/회복 제한·NPC 조합은 검토 방향이며 확정 규칙이 아니다.
- **ML AI:** 장기 연구 후보로 남긴다. 실제 플레이/AI 배틀 로그가 충분히 쌓인 뒤 행동/교체 판단·플레이 패턴 분석·팀 추천·난이도별 행동·승패 요인 분석을 검토한다. 현재 규칙 기반 AI를 즉시 교체하지 않는다.

## 현재 계획 없음

- **150/200층, 온라인 대전, PWA.** 서버/매칭/랭킹과 설치 지원을 미리 설계하지 않는다.
- 공개 서비스·유료 호스팅 전환은 현재 목표가 아니다. Windows 개인 실행기를 사용한다.
- 그 외 옛 확장 아이디어는 채택 전까지 필수 작업이나 적극적인 미래 목표로 올리지 않는다.
