# 주요 참고작과 프로젝트 방향

2026-10-04 사용자는 **PokéRogue**와 **올라라! 포켓몬 타워!**에서 큰 영감을 받았다고 명시했다. 이 두 작품을 주요 참고작으로 기록한다. 참고작의 모든 규칙을 그대로 가져오거나 현재 기술 스택을 설명 없이 변경하지 않는다.

## PokéRogue

- 사이트: https://pokerogue.net/
- 공개 소스: https://github.com/pagefaultgames/pokerogue
- 기술 연출 조사: [POKEROGUE_REFERENCE.md](POKEROGUE_REFERENCE.md)

확인 범위: 브라우저에서 한국어 타이틀/로그인 화면 확인. 계정 등록이나 로그인, 실제 배틀 플레이는 수행하지 않았다. 공개 소스에서 Phaser/TypeScript, 기술별 JSON 프레임, 효과 스프라이트 시트, 배경·소리 타이밍 이벤트를 확인했다.

[크레딧](https://github.com/pagefaultgames/pokerogue/blob/main/CREDITS.md)은 기술 애니메이션 출처를 Pokémon Reborn, 효과음을 Pokémon Emerald/Black·White로 기재한다. 즉, 포켓몬 기술 효과를 전부 새로 만든 사례가 아니다. API로 기술 영상을 받아오는 방식이 아니라 기존 리소스와 재생 데이터/코드를 결합하는 방식이다.

우리 프로젝트의 참고 기준: 포켓몬 화면, 기술의 진행 방향, 타격, HP 변화와 효과음을 맞춰 하나의 배틀 연출로 보여주는 방식. 화면의 실제 품질 비교는 대표 기술을 직접 재생해 확인할 필요가 있다. 코드/자산 파일별 이용 조건 확인이 선행되어야 한다.

## 올라라! 포켓몬 타워!

- 제작자 Young의 소개/배포 원본: https://cafe.naver.com/1209sung/18475
- 글 제목: `드디어 등장한 짭켓로그 <올라라! 포켓몬 타워!>`
- 원본 게시일: 2025-12-09. 브라우저에서 작성자와 본문을 직접 확인했다.

처음 웹 검색 도구에서는 네이버 원본을 읽지 못해 전재본/2차 자료를 확인했으나, 이후 브라우저로 원본 본문 접근에 성공했다. 게임 파일 다운로드/실행, 소스 분석, 실제 배틀 플레이는 수행하지 않았다. 소개글만으로 정확한 기술 리소스 출처나 Essentials 사용 버전을 확정하지 않는다.

제작자 소개에서 확인한 내용:

- 100층 목표의 반복 등반, 높아질수록 어려워지는 도전.
- 로비 시설·업그레이드·부적으로 이후 도전을 준비.
- 성공하면 더 높은 층에 도전할 수 있는 구조.
- 여러 종류의 층에서 육성·트레이너 배틀·포획.
- 자체 스크립트 시스템, 수정한 트레이너 AI, 일부 추가한 사운드트랙.
- 도전에 성공한 포켓몬은 다음 도전에서 사용할 수 없다는 작품 자체의 규칙.

우리 프로젝트의 참고 기준: 등반과 준비의 반복, 현재 도전과 영구 성장의 구분, 다양한 층과 네임드 트레이너/이벤트, 후반 AI 강화. 마지막 포켓몬 사용 제한이나 구체적 층 해금/손실 규칙은 우리 게임에 채택한 상태가 아니다.

## 우리 기획과 기술 선택

기존 목표인 팀 선택 → 싱글 배틀 → 승리 보상/영입 → 다음 층, 최대 6마리 보유, 출전 3마리, 영구 도감/돈/선택권 해금을 유지한다. 참고작 조사로 회복·돈 보존·해금 조건·레벨/세대의 미확정 규칙이 확정되지는 않는다.

연출의 우선순위는 기존 포켓몬 리소스/기술 연출 확보·이용 조건 확인·작은 연동 검증이다. 리소스를 찾기 전에 자체 도형/합성음으로 대체하지 않는다. 지금 확보한 Showdown 자료 22개 이미지/2개 원본 코드와 Kenney 130개 효과음은 아직 연동하지 않았다. Kenney 팩은 원작 기술 효과음과 같다는 의미가 아니다.

기술 후보:

1. 현재 웹 프로젝트에서 기존 연출을 연결하거나 배틀 영역만 Phaser로 구현하는 방식. Next.js/Node/SQLite/서버 Showdown은 유지할 수 있는 후보이며 아직 연동 검증 전이다.
2. 웹에서 원하는 품질/작업량 기준을 충족하기 어려운 것으로 확인되면 Pokémon Essentials 기반 전환을 실제 대안으로 검토한다. 전환 전에 웹·백엔드 포트폴리오 목표, 이전할 시스템과 새로 만들 부분을 설명하고 사용자 결정에 따른다.

대표 기술의 재사용 시제품이 다음 판단 근거다. 원작 수준 또는 PokéRogue 수준 품질을 확보했다고 주장하려면 실제 화면/소리 재생 확인이 필요하다. 현재 이번 조사로 게임 코드를 변경하거나 다른 엔진을 설치하지 않았다.
