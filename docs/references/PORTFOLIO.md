# 포트폴리오에 활용할 구현 설명

기준일: 2026-10-10. 아래는 실제 구현 근거를 정리한 자료이며 완성된 공개 서비스 소개가 아니다.

## 프로젝트 소개

Pokémon Tower는 포켓몬 3마리로 타워를 오르고, 상대를 영입하거나 기술·개체값을 수집해 다음 도전을 준비하는 웹 게임이다. 현재 일반 도감607종과50층을 플레이할 수 있다. 전투 규칙은 Pokémon Showdown 엔진을 사용하고 게임 흐름·화면·API 검증·저장·성장 시스템을 직접 구현했다.

## 설명할 만한 문제와 해결

| 문제 | 구현한 해결 | 확인 근거 |
|---|---|---|
| 버튼을 반복해서 누르면 행동·보상이 중복될 수 있음 | 소유권·요청 번호·합법 행동 검사, 보상 원장과 트랜잭션 | API 거부·보상 중복·롤백 검사 |
| 새로고침이나 서버 종료로 진행을 잃을 수 있음 | 초기 팀·시드·입력을 SQLite에 저장하고 엔진을 복구 | 실제 별도 서버 재시작 E2E |
| 브라우저에 상대 비공개 세팅이 노출될 수 있음 | 엔진은 서버에서 실행하고 자기 정보·상대 공개 정보만 전달 | 관측 제한·응답 데이터 검사 |
| 영구 성장과 한 번의 도전 세팅이 뒤섞일 수 있음 | 영구 프로필과 도전 스냅샷 분리, 코인·성장 포인트 분리 | 영입·성장·정산·저장 복구 검사 |
| 웹 Tab 초점으로 게임을 조작하면 선택 위치가 흔들림 | 독립 게임 커서, 방향키·Z/X, 팝업 복귀와 다음 단계 선택 | 도감·배틀·영입 키보드 E2E |
| 수백 종을 추가하면 기술·특성·이미지 예외가 늘어남 | 데이터 가져오기와 합법성 검사, 이미지 대체 처리 | 605종 엔진 검사·이미지 보고서 |

포트폴리오에서는 결과만 나열하기보다 각 문제의 재현 조건, 선택한 방법, 테스트로 확인한 범위와 남은 한계를 함께 설명한다. ‘실행 호환성 검사’를 ‘게임 밸런스가 검증됨’으로 바꾸거나 ‘로컬 복구’를 ‘대규모 운영 검증’으로 표현하지 않는다.

## 직접 만든 부분과 사용한 기반

- 직접 구현: 타워 진행·보상·영입·성장·상점·도감·검색·키보드 커서·화면·합성음·HTTP 검증·SQLite 저장과 복구·테스트.
- 사용한 기반: Showdown의 전투 엔진·종/기술 규칙·팀 검증, PokéAPI 데이터와 이미지, 외부 트레이너 그림, Neo둥근모 글꼴.
- 생성한 자료: 사용자 지정 지우 정면을 참고한 뒷모습 4프레임. 공식 원작 리소스로 소개하지 않는다.

출처·재사용 범위는 [THIRD_PARTY](THIRD_PARTY.md)에 기록한다. 포켓몬 이미지 권리와 엔진 코드 라이선스는 별개다.

## 시연 순서

1. 도감에서 검색·필터·즐겨찾기와 방향키 커서를 보여 준다.
2. 3마리 팀과 성격·포인트·기술을 설정한다.
3. 등장 알림에서 Z로 시작하고 기술·교체·C/V 상세·Shift 생략을 보여 준다.
4. 승리 후 개체값 상승과 기술 수집, 영입 또는 기술만 저장을 보여 준다.
5. 다음 층과 상점을 확인하고 새로고침 복구를 보여 준다.

서버 재시작 시연은 별도 테스트 저장으로 준비한다. 실제 사용자 진행을 초기화하거나 테스트용 조작을 정상 플레이 결과로 소개하지 않는다.
