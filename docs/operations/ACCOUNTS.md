# 계정과 기존 저장 복구

첫 접속은 로그인 화면으로 이동한다. 아이디·비밀번호로 가입하고 게임에 들어간다. 로그인한 브라우저는 30일 동안 로그인 상태를 유지하며 다시 접속하면 바로 타이틀로 이동한다. 로그아웃·쿠키 삭제·세션 만료 후에는 다시 로그인한다. 도감·배틀·설정·상점 주소를 직접 열어도 먼저 로그인하며 로그인 후 원래 화면으로 돌아간다. 회원가입 시 복구 키를 보관한 뒤 **게임으로 들어가기**를 누른다. 기본 해금은 1~9세대 스타팅 일반 최종 진화형 27종이며 배틀에는 3마리를 선택한다. 기존 도감·능력치·재화·진행 중인 도전을 유지하면서 기본 해금을 추가한다.

회원가입은 현재 게스트 저장을 계정에 연결한다. 다른 기기나 임시 주소가 바뀐 뒤에도 **같은 서버 DB에서** 같은 아이디로 로그인하면 이어서 플레이할 수 있다. 소리 설정도 로그인 계정에 저장한다. 회원가입 시 계정 복구 키를 한 번 표시하므로 파일로 보관한다. 비밀번호 찾기는 아이디와 이 키로 비밀번호를 변경하고 이전 로그인 세션을 모두 해제한다. 이메일·소셜 로그인은 제공하지 않는다.

## 원래 로컬 저장 가져오기

운영자가 로컬 DB에서 원래 플레이어를 확인한 뒤 다음 절차로 선택한 저장만 가져온다. 여러 플레이어의 데이터를 덮어쓰지 않는다.

1. `TOWER_DB_PATH`를 원본 DB로 지정하고 `node scripts/export-save.mjs 플레이어ID앞10자리` 실행. `.data/original-save.json`에 해당 플레이어의 도감·육성·재화·전체 도전과 전투 기록을 내보낸다.
2. 대상 서버 DB 백업. 테스트 서버에는 `docker compose -p tower-preview --env-file .data/preview.env -f compose.yaml -f compose.preview.yaml exec -T game node scripts/backup-db.mjs` 사용.
3. JSON을 서버 `/tmp/original-save.json`으로 복사하고 `node scripts/import-save.mjs /tmp/original-save.json /data/original-save-recovery.txt` 실행.
4. 복구 코드 파일을 본인에게만 전달하고 회원가입의 **기존 저장 복구 코드**에 입력. 가입하면 그 저장을 연결한다.

저장 복구 코드는 7일 유효하고 한 번만 사용할 수 있다. 계정 비밀번호 복구 키와 용도가 다르다. 원본 JSON에는 플레이 데이터가 있으므로 공개 폴더·Git에 넣지 않는다. 이미 계정에 연결된 저장은 추가 계정으로 가져올 수 없다.

## 운영 구조

현재 지원 SQLite 스키마는 **46**이며 계정·세션·복구 코드·소리 설정을 저장한다. 계정 기능이 처음 추가된 버전과 현재 지원 스키마를 혼동하지 않는다. 저장 구조의 기준은 [DB 안내](../engineering/DATABASE.md)다. 비밀번호는 개별 salt를 사용하는 scrypt 파생값으로 저장하며 원문을 저장하지 않는다. 로그인 쿠키는 HttpOnly/SameSite=Strict이며 HTTPS 배포에서는 Secure다. 세션 토큰은 DB에 해시만 저장한다. 로그인·복구 시도 횟수를 제한한다. 가입 후 예전 게스트 쿠키만으로 계정 저장에 접근할 수 없다.

업데이트 전 DB 백업을 보관한다. 구버전 프로그램에 새 DB를 그대로 연결하지 않는다. 되돌릴 때에는 해당 프로그램 버전의 백업도 함께 복원해야 한다. 개인 임시 터널로 공유할 때도 실제 HTTPS 주소와 DB 백업을 확인한다.
