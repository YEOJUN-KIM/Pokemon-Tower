기존에 작업 중이던 서버·밸런스·다른 화면 변경은 이번 리팩터링에서 수정하지 않았다.

## 2. select 대체

HTML select를 제거하고 공통 GameChoice를 사용하는 탭과 카드 그리드로 교체했다. 카드 전체가 선택 대상이며 기존 공통 hover·focus·게임 커서 스타일을 사용한다. 기존 Egg Station 이미지는 유지했다.

## 3. 키보드와 패드

- 방향키 / D-pad / 스틱: 그리드 이동. 마지막 행에서 아래로 이동하면 1회·10회 뽑기로 이동.
- Q/E / 패드 L·R 어깨 버튼: 탭 전환. 마지막으로 선택한 지역·타입을 기억.
- Enter/Z / 패드 A: 대상 결정 또는 뽑기 실행.
- X / 패드 B: 팝업 뒤로 또는 타이틀 복귀.
- Y / 패드 Y: 기존 알 확률 팝업. 기존 보조 키 A도 지원.
- 보상 티켓이 있으면 그리드 왼쪽에서 티켓 선택지로 이동할 수 있다.
- 하단 확률·돌아가기 명령은 마우스로 클릭할 수 있으며 Tab/방향키 탐색 대상에서 제외했다.

패드 검증은 표준 Gamepad API 입력을 모의 주입한 Chrome 자동 테스트로 수행했다. 실물 컨트롤러 검증은 수행하지 않았다.

## 4. 탭 구성

기본은 전체 뽑기 카드 1개, 지역은 3×3 카드 9개, 타입은 데스크톱 6×3 / 좁은 화면 3×6 카드 18개다. 스텔라는 기존과 동일하게 제외한다.

## 5. 지정 대상 비중

기본값은 eggMachineTuningRules.focusWeight, 증가량은 서버의 permanent.eggFocusWeight와 기본값의 차이로 계산한다. 예를 들어 `50 + 5%`에서 `+ 5`만 금색으로 표시한다. 증가량이 0이면 `50%`다. 같은 알 등급 내 선택과 대상 부재 시 기존 풀 사용 설명은 확률 팝업으로 이동했다.

## 6. 스크롤

알뽑기 화면만 100dvh 고정 레이아웃을 적용했다. 1920×1080, 1280×900, 390×844, 360×640, 320×568, 844×390에서 모든 탭을 검증했다. 문서 가로·세로 스크롤, 카드 영역 이탈, 하단 안내 잘림이 없는 것을 확인했다. 기존 부화 결과 팝업 내부 스크롤은 유지한다.

## 7. 뽑기 로직 보존

서버·도메인·데이터 구조는 이번 작업에서 수정하지 않았다. 기존 요청과 send 처리, 1회·10회 가격 계산, 티켓 우선 차감, 지역·타입 지정, 영구 연구 효과, 보상 티켓, 연출·결과·저장 처리를 그대로 연결했다. 테스트에서 지역 10회는 티켓 2장 + 2,000P, 이어지는 타입 1회는 250P로 실제 차감되는 것을 확인했다.
