# 데이터 표시·NPC·이벤트 장면 정리 (2026-10-20)

## 반영 내용

- 이벤트 결과와 후속 문구에서도 플레이어(좌측 하단)와 해당 이벤트 대상(우측 상단)을 유지한다. 빌런·히든 보스·일반 NPC·선택한 도전자·미러·상자·레이드 결과에 적용했다. 히든상점은 기존 상품 목록/상세 구성을 유지한다.
- NPC 결과에 붙던 상자 보상용 빛과 별을 제거했다. 이 효과는 상자에만 남는다. 크세로시키의 결과 화면을 PC/모바일로 확인했다.
- 일반 배틀 상대, 이벤트 NPC, 도전자 이미지를 공통 `TrainerPortrait`로 연결했다. 일반 원화나 스프라이트 시트를 단독 배틀 이미지로 표시하지 않는다.
- 영양제 설명은 실제 증가값과 능력치 이름을 표시한다. 포켓몬 선택 카드는 개별 누적 사용 횟수를 표시하며, 한도에 도달하면 기존 비활성화와 사유를 유지한다.
- 메가스톤과 폼 전용 도구는 주 효과와 실제 보호 범위를 설명한다. 공통 기믹 사용 제한 문구는 메가스톤 설명에서 제거했다.
- 동적 기술 타입은 현재 엔진 상태의 네이티브 콜백으로 구한다. 버튼·타입 배지·아이콘·테두리·상세·모바일 툴팁이 같은 결과를 사용한다.

## NPC 에셋 점검

`public/sprites/trainers/sources.json`의 출처·검수 정보와 PNG 크기를 확인하고, 트레이너 카탈로그·빌런 메타데이터·이벤트 표시 레지스트리의 참조 키를 대조했다. 모든 파일을 새로 그리거나 다운로드하지 않았다.

| 분류 | 수 | 처리 |
| --- | ---: | --- |
| 배틀 픽셀 스프라이트 | 194 | 공통 렌더러에서 허용 |
| 플레이어 스프라이트 시트 | 2 | 기존 플레이어 애니메이션에서만 잘라 사용 |
| 일반 원화 | 1 | 배틀/NPC 이미지로 선택하지 않음 |
| 참조된 파일 누락 | 0 | 등록된 참조 키 대조 결과 |

일반 원화는 **아케비(`aliana`, 270×431)** 한 건이다. 출처는 기존 manifest의 Bulbagarden `XY_Aliana.png`이며 `original-game-character-artwork`로 표시되어 있었다. 대응 도트 스프라이트가 없으므로 기존 에이스 트레이너 픽셀 이미지의 검은 실루엣을 사용한다. 파일 자체를 삭제하거나 다른 캐릭터라고 표시하지 않으며 이름/대체 텍스트는 아케비로 유지한다.

`player-back-sheet`와 `ash-johto-back-sheet`는 애니메이션 시트이다. 미러 도전자는 기존 `player-front.png` 픽셀 이미지를 사용한다. 별도의 픽셀 초상화 fallback이나 사진 파일 참조는 발견하지 못했다. 이미지 로딩 실패/알 수 없는 키도 공통 실루엣으로 처리한다.

에셋 분류는 기존 출처 정보와 파일 규격에 기반한 점검이다. 재생성 도구는 `scripts/audit-trainer-assets.mjs`, 결과는 `src/data/trainer-assets.json`이다. 새 에셋을 추가할 때에는 출처와 실제 이미지 종류를 함께 검수해야 한다.

## 영양제의 기준 데이터

- 실제 적용: `src/server/inventory-grants.ts`의 `applyVitamin`.
- 증가량: `src/data/shop.ts`의 `VITAMIN_BOOST = 5`.
- 개별 누적 한도: `VITAMIN_LIMIT = 3`.
- 누적 사용량: `vitamin_purchases`의 Run/포켓몬별 행 수.
- 실제 증가분: `run_stat_boosts.points`에 누적한다. 원작 노력치 환산치를 설명에 임의로 추가하지 않았다.
- 같은 층에서 같은 종류를 한 번만 사용할 수 있는 기존 규칙도 유지한다.
- 예: `키토산` → `특수방어 능력 포인트를 5 올린다.` / 대상 카드 → `영양제 사용 1 / 3`.

설명은 `vitaminDescription`을 배낭과 히든상점이 공유한다. 히든상점의 기존 저장 스냅샷도 표시 시 최신 설명을 사용한다. 저장된 상품, 가격, 구매 여부, 보상 효과는 변경하지 않는다. 배낭과 즉시 사용 대상 선택 모두 같은 포켓몬별 사용량을 표시한다.

## 도구 설명과 실제 보호 범위

메가스톤은 `mega-items.json`의 대상/메가폼 메타데이터로 설명을 생성한다. 플레이트·메모리·카세트·가면·녹슨검/방패는 `form-items.ts`의 기존 가족/타입 정보로 설명을 생성한다. 주홍구슬·쪽빛구슬도 원시회귀 효과와 보호 범위를 표시한다.

대응 포켓몬이 지닌 메가스톤·전용 폼 도구에는 엔진의 `onTakeItem` 보호가 적용된다. 대표 6개 도구를 탁쳐서떨구기·트릭·도둑질로 실제 공격해 18개 사례에서 유지되는 것을 확인했다. 이 보호를 모든 도구나 모든 포켓몬에 확대하지 않았다.

**도구 제거 방지와 효과 억제는 다르다.** 금제/매직룸에서는 플레이트·메모리·카세트의 타입 판정이 노말로 돌아갈 수 있다. 가면을 지닌 오거폰의 덩굴방망이는 현재 폼에 따라 타입을 유지하며, 도구의 위력 보정은 억제될 수 있다. 주홍구슬/쪽빛구슬은 네이티브 `ignoringItem`에서 원시회귀 도구 예외를 적용한다. 따라서 모든 메가스톤·전용 도구가 효과 무효화를 받지 않는다는 포괄 문구를 넣지 않았다.

## 동적 기술 타입의 기준

`src/battle/move-preview.ts`는 현재 배틀의 격리된 스냅샷에서 엔진의 `ModifyType`/`ModifyMove` 콜백을 실제 공격 처리와 같은 순서로 실행한다. 엔진에 등록된 기술·특성·도구·날씨·필드 규칙을 재사용하며 UI별 기술 이름 switch를 추가하지 않았다.

라이브 PRNG, 프로토콜, 도구, 특성, 폼은 변경하지 않는다. Tower의 별도 능력치/기믹 예산 이벤트는 타입을 바꾸지 않으며 직렬화할 수 없는 이벤트 참조를 미리보기에서 제외한다. 기존 로컬 Dex 패치는 그대로 사용한다. 매 요청마다 다시 계산하므로 전투 중 폼/필드/억제 상태 변화도 다음 기술 선택에 반영된다.

`BattleSession.movePP.type/category`를 버튼과 상세가 공유한다. 기술의 기본 데이터만 사용하던 덩굴방망이·잠재댄스·오라휠 및 특성/날씨 기반 타입을 수정했고, 기존 별도 플레이트/메모리/카세트 계산도 네이티브 판정으로 통일했다. 새 전투 규칙이나 데미지 배율을 추가하지 않았다. 미리보기는 현재 상태 기준이며 아직 선택하지 않은 상대 행동에 따른 미래의 타입 변화를 예언하지 않는다.

| 필수 기술 | 엔진 실제 공격과 비교한 범위 |
| --- | --- |
| 덩굴방망이 | 기본/우물/화덕/주춧돌 4종 |
| 심판의뭉치 | 기본 노말 + 플레이트 17종 |
| 멀티어택 | 기본 노말 + 메모리 17종 |
| 테크노버스터 | 기본 노말 + 카세트 4종 |
| 잠재댄스 | 춤추새 4가지 스타일 |
| 오라휠 | 배부른/배고픈 모습 |

추가 검증: 웨더볼, 대지의파동, 레이징불, 테라버스트, 테라클러스터, 잠재파워, 자연의은혜, 페어리스킨/스카이스킨/프리즈스킨/일렉트릭스킨/촉촉보이스/노말스킨. 금제·매직룸의 기술 타입 억제와 해제도 비교했다.
