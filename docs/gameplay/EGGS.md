# 알 종류와 부화

기준: 2026-10-16. 아래 현재 구현 설명은 기계식 공통 뽑기 기준입니다. 등급별 뽑기·티켓은 하단의 향후 확장으로 구분합니다. 기계에서 1회·10회 뽑기를 진행하며 알 종류는 직접 선택하지 않습니다. ‘알 확률’ 팝업은 일반·레어·슈퍼레어를 가로 한 줄로, 별도 이로치 판정은 아래 독립 영역으로 표시합니다. 좁은 화면에서는 세로로 배치합니다. 타입별 알은 제외했습니다.

## 종류와 가격

| 알 | 외형 | 뽑기 결과 |
|---|---|---|
| 일반 알 | 흰색 바탕과 초록 문양 | 일반 포켓몬, 이로치 아님 |
| 레어 알 | 무지개 문양, 보라·청록 오라와 에너지 회전 | 준전설·패러독스·울트라비스트 중 하나, 이로치 아님 |
| 슈퍼레어 알 | 백금색과 연보라 문양, 느린 후광과 별빛 | 초전설·환상 중 하나, 이로치 아님 |
| 이로치 알 | 황금색, 금빛 반짝임 | 모든 등급에서 이로치 확정 |

모두 1회 200 성장 포인트입니다. 공통 알 뽑기권을 먼저 사용하고, 부족한 횟수만 포인트로 결제합니다. 1회·10회 뽑기를 지원하며 별도의 종류별 티켓은 없습니다.

## 확률과 대상

- 먼저 포켓몬 등급을 일반 85% / 레어 12% / 슈퍼레어 3%로 추첨하고, 그 포켓몬에 별도로 0.24% 이로치 판정을 적용합니다. 모든 등급에 동일하게 적용하며 등급 확률에서 0.24%를 먼저 떼지 않습니다. 알마다 독립적으로 처리하고 10회 뽑기에도 같은 규칙을 사용합니다.
- 일반 풀에는 전설·준전설·환상·패러독스·울트라비스트를 포함하지 않습니다.
- 레어 안의 준전설·패러독스·울트라비스트 비중은 기존 상대 비율 45:25:15를 유지합니다. 각각 9/17, 5/17, 3/17입니다. 초전설·환상은 레어에 포함하지 않습니다.
- 슈퍼레어 안에서는 초전설:환상 비율이 5:1입니다. 전체 뽑기 기준 초전설 2.5% / 환상 0.5%입니다. 각 분류 안에서는 대상 포켓몬을 균등하게 선택합니다. 내부 분류 비중은 팝업에서 표시하지 않습니다.
- 배틀에 사용할 수 있는 수집 도감 항목만 대상입니다. 패러독스·울트라비스트는 엔진 종 데이터의 태그로 먼저 분류하며 다른 희귀 분류와 중복시키지 않습니다.
- 이로치가 당첨되면 등급과 관계없이 황금 알로 표시합니다. 실제 외형 비율은 일반 84.796%, 레어 11.9712%, 슈퍼레어 2.9928%, 이로치 0.24%입니다. 팝업은 세 등급의 확률과 별도 이로치 판정 확률을 구분해 표시합니다.

현재 뽑기 대상은 일반 496개 / 레어 71개 / 슈퍼레어 48개(초전설 25개·환상 23개)입니다. 별도 수집하는 리전폼도 각각 한 항목으로 셉니다. [전체 등급 목록](../../artifacts/reports/changes/EGG_POOL_CLASSIFICATION.md)을 참고합니다.

이 비중은 준전설을 높이고 전설·환상을 낮추려는 사용자 방향을 반영한 초기 구현값입니다. 게임 전체 난이도·경제 조정은 후속 작업입니다.

## 개별 부화와 한 번에 열기

1. 알 뽑기 탭의 기계에서 1회 또는 10회 뽑습니다. 각 알마다 분류·이로치 판정을 별도로 처리해 종류가 섞여 나올 수 있습니다. 사용자 제공 기계가 들썩인 뒤 출구에서 대표 알 하나가 나옵니다. 대표 알은 실제 결과의 가장 높은 등급으로, 이로치 > 슈퍼레어 > 레어 > 일반 순입니다. 10회도 열 개를 차례로 배출하지 않고 약 1.6초의 한 번 연출 뒤 결과 알 열 개를 펼칩니다. 서버 응답 대기 시간은 별도이며 동작 감소 설정에서는 연출을 단축합니다.
2. 받은 알을 닫힌 상태로 나열합니다. 이로치면 황금 알, 그렇지 않으면 일반·레어·슈퍼레어 등급의 알로 표시합니다.
3. 원하는 알을 터치하거나 키보드로 선택하면 흔들림·빛 연출 후 그 알의 포켓몬을 공개합니다.
4. ‘한 번에 열기’는 남은 알을 함께 부화시킵니다. 이미 열린 알을 다시 추첨하지 않습니다.
5. 모두 열린 뒤 ‘확인’으로 닫습니다. 부화 전 X/닫기를 누르면 남은 알을 먼저 열고, 결과를 확인한 뒤 닫을 수 있습니다.

레어 알은 준전설·패러독스·울트라비스트, 슈퍼레어 알은 초전설·환상 중 하나라는 것을 알려주며 정확한 포켓몬은 부화 후 공개합니다. 황금 알은 이로치 확정임을 알려줍니다. 새 포켓몬 표시, 개체치 개선, 새 기술과 이로치 해금 결과를 유지하며 분류는 결과 배경으로 구별합니다. 슈퍼레어는 백금빛·연보라 후광과 느리게 떠오르는 별빛을 사용합니다. 동작 감소 설정에서는 회전·반짝임을 정지하고 짧은 부화 전환을 사용합니다.

## 부화 결과 배경

부화 팝업은 최대 1,500px, 화면 너비의 96%까지 확장합니다. 큰 PC 화면에서는 카드 5개씩 두 줄로 배치하고 능력치를 두 칸씩 표시합니다. 작은 화면이나 결과 내용이 길어지는 경우에는 결과 영역만 스크롤하며 확인 버튼은 아래에 유지합니다.

## 저장과 중복 처리

추첨·재화 차감·도감/개체치/기술/이로치 해금·구매 영수증은 하나의 서버 트랜잭션에서 먼저 저장합니다. 알 터치와 전체 열기는 저장된 결과를 공개하는 화면 동작이며 추가 결제·추첨·지급을 하지 않습니다. 같은 요청 번호로 재전송하면 동일한 결과를 반환하고, 횟수나 구매 내용이 바뀌면 거부합니다. 클라이언트가 알 종류를 보내도 기계 추첨을 우회하지 못합니다. 과거 결제된 종류 선택형·일반 알 영수증은 원래 결과로 복구합니다.

새 포켓몬은 도감에 등록합니다. 중복은 더 높은 개체치·새 기술·이로치 외형을 모으는 기존 규칙을 사용합니다. 이미 이로치인 포켓몬을 다시 뽑아도 별도 포인트나 교환권을 돌려주지 않습니다. 별도 부화 대기·걸음 수·알 보관함은 없습니다. 새로고침하면 도감과 재화는 유지되지만, 현재 부화 공개 화면을 이어서 보여주는 기능은 없습니다.

## 뽑기기계 조정 (Tuning)

서버·도메인 로직과 요청 타입을 구현했습니다. **조정 버튼·선택 화면·모달·CSS 등 UI는 아직 미구현이며 후속 작업**입니다. 기존 화면은 조정 없이 공통 뽑기를 그대로 사용합니다. 타입별 전용 알이나 별도 뽑기기계를 추가하는 기능이 아닙니다.

| 모드 | 1회 포인트 가격 | 10회 포인트 가격 | 집중 대상 |
|---|---:|---:|---|
| 기본 / 조정 없음 | 200P | 2,000P | 기존 공통 풀 |
| 지역 집중 | 250P | 2,500P | 선택한 지역에서 처음 등장한 종·형태 |
| 타입 집중 | 250P | 2,500P | 선택 타입을 하나라도 가진 종 |
| 이벤트 기간 한정 집중 | 250P | 2,500P | 서버에 등록된 이벤트의 지역·타입·종 목록 조건 |

표는 티켓을 사용하지 않았을 때의 가격입니다. 기존 공통 알 뽑기권을 먼저 1회당 1장 사용하며 조정 뽑기도 한 장으로 한 회를 결제합니다. 남은 횟수만 해당 모드의 포인트 가격으로 계산합니다. 10회 할인·추가 보장·천장은 없습니다. 가격은 `permanentPrices.egg`와 `eggMachineTuningRules.focusedPrice`, 집중 가중치는 `eggMachineTuningRules.focusWeight/otherWeight`에서 관리합니다.

### 집중 규칙과 기존 확률

집중은 **확정 출현이 아니라 확률 상승**입니다. 각 알에서 기존 일반 85% / 레어 12% / 슈퍼레어 3%로 등급을 먼저 결정합니다. 해당 등급의 유효 후보를 집중 대상과 나머지로 나눈 뒤 초기 가중치 **50:50**으로 그룹을 선택합니다. 나머지 지역에 각각 6.25%를 배분하지 않습니다. 그룹 내 일반 종은 균등 추첨하고, 희귀 등급은 아래의 내부 분류 가중치를 거쳐 종을 균등 추첨합니다.

- 집중 그룹이 비어 있으면 해당 등급의 비집중 후보 전체를 사용합니다.
- 비집중 그룹이 비어 있으면 해당 등급의 집중 후보 전체를 사용합니다.
- 비어 있는 그룹 때문에 등급을 다시 추첨하거나 다른 등급으로 바꾸지 않습니다. 양쪽에 후보가 있을 때 집중 비중이 50%이며, fallback이 일어나면 그 등급의 집중 비중은 0% 또는 100%입니다. 따라서 전체 결과에서 항상 50%를 보장하는 것은 아닙니다.
- 레어의 그룹 안에서는 기존 준전설:패러독스:울트라비스트 가중치 45:25:15를 사용하되 **선택한 그룹에 후보가 있는 분류만** 남겨 재정규화합니다. 슈퍼레어도 같은 방식으로 초전설:환상 5:1을 사용합니다. 예를 들어 호연 집중 레어 그룹에 패러독스·울트라비스트가 없으면 유효한 준전설 후보에서 정상 추첨합니다. 분류 태그와 등급 소속은 바꾸지 않습니다.
- 집중 50%를 유지하기 위해 조정 중인 결과의 **최종 희귀 내부 분류 비중**은 후보 구성에 따라 기본 뽑기와 달라질 수 있습니다. 조정 없는 뽑기의 기존 내부 비중과 추첨 순서는 그대로 유지합니다.
- **등급 85/12/3%와 별도 이로치 0.24%는 조정으로 변경하지 않습니다.** 이로치 판정과 도감 등록·IV 개선·기술 수집·이로치 해금은 기존 처리를 사용합니다. 10회도 각 결과에 같은 조정을 독립 적용합니다.

### 지역·타입 데이터

지역 키는 `kanto`(관동), `johto`(성도), `hoenn`(호연), `sinnoh`(신오), `unova`(하나), `kalos`(칼로스), `alola`(알로라), `galar`(가라르), `paldea`(팔데아)입니다. 기존 지역 데이터의 키·이름·등장 시점과 종/형태 메타데이터를 재사용하며 별도의 대형 종 목록을 만들지 않습니다.

기존 `selectableForms.region`을 우선 사용하고, 엔진의 리전폼 이름과 해당 형태의 등장 메타데이터를 보완적으로 사용합니다. 나옹은 관동, 알로라 나옹은 알로라, 가라르 나옹은 가라르입니다. 울트라비스트는 알로라, 패러독스는 팔데아로 분류됩니다. 지원 지역을 9개로 유지하므로 **히스이 형태와 히스이에서 처음 등장한 진화형은 신오로 묶습니다.** 이 판정은 수집 자격을 추가하지 않습니다. 기존처럼 별도 수집하는 리전폼은 별도 종 식별자를 유지하고, 수집 대상이 아닌 형태를 뽑기 풀에 새로 넣지 않습니다.

타입은 현재 게임·엔진이 사용하는 `teraTypes`의 타입 목록을 재사용합니다. 복수 타입은 어느 한쪽과 일치하면 대상입니다. 예를 들어 Fire/Flying인 리자몽은 불꽃 집중과 비행 집중 모두에 포함됩니다. 해당 타입 보유 후보가 없는 등급에서는 위 fallback을 사용합니다.

### API·이벤트 확장·영수증

기존 `POST /api/battle`의 영구 상품 요청에 선택적 `tuning`을 전달합니다. 타입은 `EggMachineHatchRequest` / `EggMachineTuning`입니다.

```json
{
  "type": "permanent",
  "requestId": "eb7fc34a-45cb-4d6c-80ee-1dcf0ca9e062",
  "action": "hatch",
  "product": "egg",
  "count": 10,
  "tuning": {"kind": "region", "region": "hoenn"}
}
```

- 생략 또는 `{"kind":"none"}`은 같은 기본 뽑기입니다. 타입 집중은 `{"kind":"type","pokemonType":"Fire"}`, 이벤트 집중은 `{"kind":"event","eventId":"서버에-등록된-ID"}`입니다. 한 번에 한 가지 조정만 지원합니다.
- 가격·가중치·후보 목록은 서버에서 결정합니다. 알 수 없는 지역·타입·이벤트·모드, 필수 값 누락과 조정 객체의 임의 추가 필드는 기존 오류 형식으로 400을 반환합니다. 조정은 공통 기계식 부화에만 적용하며 티켓 구매·이로치 교환·과거 종류 선택형 뽑기를 변경하지 않습니다.
- `eggTuningEvents`는 현재 빈 서버 정의 목록입니다. 실제 기간 한정 이벤트 콘텐츠와 일정 시스템은 구현하지 않았습니다. 향후 개발자가 `id`와 `targets`를 등록하면 지역·타입·명시적인 종 목록을 조건으로 사용할 수 있습니다. 여러 target은 OR로 결합하며 클라이언트는 ID만 전송합니다.
- 정규화한 조정 정보를 기존 영수증 JSON에 포함합니다. 같은 요청 번호·같은 조정은 저장된 결과를 반환하고 재결제·재추첨하지 않습니다. 다른 조정으로 바꾸면 기존 정책대로 409를 반환합니다. 조정 생략과 명시적 none은 같은 요청으로 취급하며 기존 영수증 형태도 유지합니다.
- 이미 결제된 이벤트 영수증은 이후 이벤트 정의가 없어져도 같은 ID로 재전송하면 원래 결과를 반환합니다. 등록되지 않은 이벤트로 새 구매를 하는 것은 거부합니다. DB 스키마 변경 없이 기존 영수증과 트랜잭션을 사용합니다.

구현 위치는 `src/data/egg-machine-tuning.ts`(타입·서버 설정·이벤트 정의), `src/game/egg-machine-tuning.ts`(순수 가중치 선택), `src/server/egg-machine-tuning.ts`(검증·지역·타입 판정·유효 분류 선택), `src/server/permanent-shop.ts`(가격·기존 부화·영수증 연결)입니다. 관련 결정론적 검사와 API/저장 복구 검사는 `tests/egg-machine-tuning.test.ts`, `tests/egg-machine-tuning-api.test.ts`에 있습니다.

## 향후 확장: 등급별 뽑기와 전용 티켓

**구현 방향 확정, 세부 규칙은 추후 결정**입니다. 현재 무작위 등급의 공통 뽑기와 별개로 다음과 같은 등급별 뽑기를 지원하는 방향입니다.

- 일반 알 뽑기.
- 희귀 알 뽑기.
- 초희귀 알 뽑기.
- 이로치 관련 뽑기·획득 방식.

각 뽑기는 별도 티켓이나 조건을 사용할 수 있습니다. 현재의 일반·레어·슈퍼레어·이로치 알 표시와 등급 체계를 기준으로 검토하되, 기획의 희귀·초희귀와 현 등급의 정확한 대응·상품 이름은 추후 결정합니다. 타입별 알 제외 결정을 되돌리는 내용은 아닙니다.

[히든 상인](EVENT_CANDIDATES.md#4-히든-상인)이 희귀 알·희귀 알 뽑기권·초희귀 알 뽑기권 등 영구 수집 상품을 **영구재화로 판매**할 수 있습니다. 모든 상품의 상시 판매를 보장하지 않으며 희귀 티켓의 진열 자체도 희귀할 수 있습니다. 독립 이벤트 후보였던 브리더의 알 선택은 삭제하고 이 상품 역할을 히든 상인으로 흡수했습니다. 현재 브리더 선물·여행 상인이 공통 알 티켓을 지급하는 구현은 별도로 유지됩니다.
