# 문서와 파일 관리

2026-10-11 정리 기준.

## 문서 역할

- `STATUS.md`: 현재 실제 게임의 규칙, 적용 상태, 검증 범위.
- `SESSION_HANDOFF.md`: 마지막 완료 작업·다음 시작점·입력 경로. 과거 소식을 계속 맨 위에 누적하지 않는다.
- `ROADMAP.md`: 다음 후보·완료 기준·보류 항목.
- `docs/experiments/README.md`: 실험 순서와 채택/보류/게임 적용 구분.
- 기능/실험 문서와 `DEVLOG.md`: 당시 변경·수치·근거. 과거 결과를 현재 규칙으로 덮어쓰지 않는다.
- `docs/README.md`, `scripts/README.md`, `artifacts/README.md`: 영역별 입구.

새 변경은 담당 문서와 현재 요약을 함께 갱신한다. 가격·키 조작 같은 값은 코드와 확인하고, 오래된 문서가 현재값처럼 보이면 작성 시점과 최신 문서 링크를 명시한다. 실험 플레이어 버전과 실제 상대 AI 버전을 구분한다.

## 원자료 보존

2026-10-12 Git 정리: 로그·경기/턴 JSONL·중간 PNG/GIF·미리보기 WAV 920개는 Git 추적에서 제외하고 로컬에 보존했다. 기존 추적 파일 중 팀 샘플·manifest·요약·검증 보고서와 현재 문서에서 직접 링크한 이미지 등 408개는 유지한다. 게임 코드·실행 자산·테스트 입력 JSON은 제외하지 않았다. 새 PC의 과거 실험 재생·감사에는 로컬 원자료가 필요하며 일반 게임 실행에는 필요하지 않다. Git 이력 재작성은 하지 않는다.

기존 artifacts와 실험 scripts/lib 경로는 runner·테스트·manifest가 사용하므로 이번 정리에서 이동/삭제하지 않았다. 파일명 규칙으로 찾을 수 있도록 목록을 추가했다. 새 자료의 경로를 바꾸려면 호출자·문서 링크·테스트와 해시 보존 방안을 함께 검토한다.

원자료와 DB는 서로 다르다. `.data/`의 실제 저장이나 서버 상태는 문서 정리 대상으로 삭제하지 않는다. 새 실험은 새 ID와 manifest를 사용한다. 과거 입력·소스 해시가 다르면 불일치를 기록하고 의도한 새 버전으로 검증한다.

색인 갱신은 `node scripts/index-artifacts.mjs`다. 생성 파일은 `artifacts/index.json`과 `index.md` 두 개다. 파일의 크기와 위치를 조사할 뿐 전체 무결성 감사나 재시뮬레이션을 수행하지 않는다.

## 이번 정리와 검증

정리 전 핵심 문서8개의 원문을 [archive 안내](../archive/README.md)와 SHA-256 목록으로 보존했다. 현재 입구·인계·로드맵·요구사항·조작·설치 문서를 최신화하고 실험/스크립트/원자료 색인을 추가했다. 동결된 시뮬레이션 파일과 게임 소스는 변경하지 않았다.

확인은 현재 Markdown의 로컬 파일 링크(코드 블록 제외, 원문 archive 제외), archive8개 해시, 색인과 실제 파일 크기 일치·원자료 경로 보존, 색인 재생성 일치로 수행한다. 실행/밸런스 재검증을 새로 했다고 표시하지 않는다. `snapshots.json`은 정리 전 문서 해시로 이후 현재 문서와 일치하지 않는 것이 정상이다.

검증 완료: 핵심 원문8개 해시 일치, 최근 두 실험 manifest의 소스/입력 해시146개·150개 일치, 원자료 색인1,227개 파일/23개 manifest와 실제 크기 일치, 색인 재생성 결과 동일. 로컬 문서 링크 검사를 수행했고 끊어진 파일 링크는 없었다. 이번에는 게임 실행·밸런스 테스트를 새로 돌리지 않았다.
