# ADR 002 — 단일 서버의 웹 한 경기

날짜: 2026-10-04. 상태: 로컬 프로토타입에 채택.

## 결정

Next.js App Router의 페이지와 Node.js Route Handler를 사용한다.
Showdown은 serverExternalPackages로 외부 모듈로 실행해 배틀 데이터와 동적 로딩 경로를 유지한다.
배틀은 기존 runBattle을 재사용하고 사람의 Policy 입력만 HTTP 요청으로 연결한다.

## 이유와 대안

턴제 싱글플레이에서는 서버가 행동을 받아 다음 선택 지점까지 실행한 결과를 응답하면 충분하다.
첫 단계에 WebSocket이나 별도 NestJS 프로세스는 도입하지 않는다.
DB 설계 전에 화면·엔진 통합을 독립적으로 검증하기 위해 메모리 세션을 사용한다.

## 제약과 검증

- 브라우저 새로고침 복귀는 HttpOnly 쿠키와 살아 있는 단일 서버 메모리를 이용한다.
- 서버 재시작·다중 인스턴스·서버리스에는 이 방식이 적합하지 않다. 진행 상태 저장 단계에서 변경한다.
- 행동 번호는 턴 번호와 별개다. 한 턴 안의 기절 교대도 다른 requestId를 가진다.
- 중복 행동·잘못된 소유자·허용되지 않은 특수 기믹 입력을 서버가 거부한다.
- NextURL이 127.0.0.1을 localhost로 정규화하므로 Origin을 실제 Host 기준으로 비교한다. 프록시 환경은 TOWER_ORIGIN을 명시한다.
- 이미지 제공과 기술 연출은 분리한다. 기존 스프라이트를 표시하고 HP·등장·처리 중 효과는 CSS로 구현한다.
- 실제 기술별 애니메이션이나 순차적인 전투 타임라인 재생은 아직 없다. 한 행동 응답 후 턴 결과를 함께 표시한다.

## 재검토

다음 단계에서 DB 트랜잭션·보상 멱등성·저장 복구를 설계한다.
사용자 계정과 서버의 운영 제한은 공개 배포 전에 결정한다.
