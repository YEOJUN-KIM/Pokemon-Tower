# 도감 통합 포켓몬 설정

## 구현 결과

능력치 조정과 기술배치 진입점을 하나의 `PokemonSettings` 팝업으로 연결했다. 왼쪽은 HP·공격·방어·특수공격·특수방어·스피드·성격·성별, 오른쪽은 기술 4칸·특성·테라스탈 순서다. 포켓몬 이미지와 정체성, 배분 합계, 보유 성장 포인트는 상단에 함께 표시한다. 기존 밝은 도감 목록은 유지하고 세팅 팝업은 짙은 남색, 약간 둥근 테두리, 공통 청록 선택색으로 구성했다.

참고 이미지의 역할을 각각 반영했다: 이미지 1의 포켓몬과 두 영역 정보 배치, 이미지 2의 큰 능력치와 게이지·MIN/MAX, 이미지 3의 성격 보정 축, 이미지 4의 상세 기술 행이다.

## 컴포넌트

새 컴포넌트는 `PokemonSettings`, 내부 `SettingsPicker`와 `FormPicker`, 공통 `GameMenuProvider`와 `GameMenuBar`다. `PokedexDialog`, `GameMenuFooter`, `GameChoice`, `GameChoiceList`, `NatureMatrix`, `FormEditor`, `PokemonImage`, `TypeBadge`, `MoveCategoryBadge`, `TeraTypeIcon`을 재사용했다.

## 키보드·패드·마우스

- 메인 ↑↓: 현재 컬럼의 활성 행을 순서대로 이동한다. ↓ 마지막에서 저장 가능한 경우 저장 행에 진입한다.
- 메인 ←→: 같은 순번의 반대 컬럼으로 이동한다. 행 수가 짧으면 마지막 활성 행을 사용한다.
- Enter/Z: 현재 항목을 선택한다. Esc/X: 현재 팝업만 닫는다.
- 하위 팝업을 닫으면 열었던 항목에 복원한다. 메인을 닫으면 도감 카드 또는 진입했던 출발 파티 슬롯에 복원한다.
- 기존 패드 매핑이 같은 키보드 처리 경로를 사용한다. 행 전체 클릭과 range 드래그도 지원한다.

## footer

도감 화면에는 `GameMenuFooter` DOM이 하나만 있다. `GameMenuProvider`에 팝업이 안내를 등록하고, 마지막으로 등록된 활성 팝업만 표시한다. 닫힐 때 해당 등록을 제거하므로 이전 안내가 복원된다.

컨텍스트는 `dex`, `pokemon-settings`, `ev-editor`, `nature-picker`, `move-picker`, `ability-picker`, `tera-picker`, `form-picker`, 일반 `dialog`다. 팝업 내부 footer와 기존 선택 메뉴의 중복 키 안내 문장을 제거했다. 활성 팝업 중에는 배경의 즐겨찾기 버튼 및 F/R/도전 시작 안내를 표시하지 않는다.

footer는 동일한 화면 하단 위치와 높이를 유지한다. 네이티브 dialog가 배경을 비활성화·어둡게 만드는 동안에도 기존 footer 하나를 manual popover의 top layer로 표시해 읽을 수 있게 했다. footer를 팝업 안에 복제하거나 옮기지 않는다. 팝업은 footer 위 공간 안에서 끝나고 긴 기술·모습 목록만 내부 스크롤한다. 배경 blur는 사용하지 않는다.

## 편집과 저장

| 항목 | 동작 |
| --- | --- |
| 능력 포인트 | 큰 결과 능력치·현재 투자·전체 /66 표시. ←→로 1씩, Q=MIN, E=MAX. 마우스 게이지와 MIN/MAX도 지원. 항목 0~32, 합계 66 제한. 키는 `settingsKeys`에서 변경한다. |
| 성격 | 기존 25칸 matrix 재사용. 행은 상승 ↑, 열은 하락 ↓, 중립은 보정 없음. 커서·마우스 위치의 보정과 해당 축을 미리 보여 주고 선택 시 반영한다. |
| 성별 | 별도 팝업 없이 가능한 성별을 순환한다. 무성·고정은 비활성 행과 상태 텍스트로 표시한다. |
| 기술 | 보유 기술과 현재 모습의 사용 가능 기술의 교집합만 표시한다. 이름·타입·분류·위력·명중·PP·설명을 제공한다. 다른 슬롯의 기술은 비활성화하고 ‘이미 장착됨’을 표시한다. |
| 기술 수 예외 | 메타몽처럼 보유 기술이 적으면 빈 칸을 무리하게 채우지 않는다. 빈 칸은 앞에서부터 추가하며, 사용할 미배치 보유 기술이 없으면 비활성화한다. 저장 배열에 빈 구멍이나 중복이 생기지 않는다. |
| 특성 | 현재 모습에서 실제 가능한 특성과 기존 설명만 표시한다. |
| 테라스탈 | 기존 허용 타입 목록과 전용 타입 제한을 사용한 아이콘 grid다. |
| 모습 | 기존 FormEditor와 저장된 모습별 설정을 재사용한다. 대상 모습의 능력치·특성·기술 후보를 함께 반영하고 기존 무료 모습 변경 비용 계산을 유지한다. |

하위 적용은 메인 편집 상태에 반영한다. 하위 취소는 해당 변경을 버린다. 메인의 **설정 저장**에서 기존 `train` API, revision, 성장 포인트 비용 계산을 그대로 사용해 한 번 저장한다. 메인을 저장하지 않고 닫으면 편집 내용을 버린다. IV는 표시만 하며 기존 영입 기반 변경 규칙을 유지한다. 진행 중 도전의 설정과 배틀 룰·밸런스는 변경하지 않았다.

## 기존 구조에서 발견한 점과 남은 후보

- 기존 도감은 능력치/특성 탭과 별도 MoveEditor에 설정이 흩어졌고 팝업 내부와 바깥 footer가 중복됐다. 이번 도감 경로를 통합했다.
- 기존 공통 CSS의 높은 우선순위가 팝업 높이를 덮어썼다. 관리되는 팝업에 제한 범위를 명시하고 내부 목록만 스크롤하게 보완했다.
- 모습별 기술 후보가 기존 응답에는 없어서, 기존 서버 데이터에서 메타데이터만 추가했다. 저장 검증·비용 규칙은 바꾸지 않았다.
- 일반/숨겨진 특성 구분 정보는 현재 TrainingView에 없으므로 추정 태그를 붙이지 않았다. 메타데이터를 추가하면 같은 목록에 확장 가능하다.
- ‘배울 수 있는 전체 기술’ 도감 영역은 요청에 따라 별도 후속 작업으로 남겼다.
- 배틀 정비의 기존 TrainingEditor/MoveEditor와 다른 화면들의 내부 footer는 이번 도감 provider 범위 밖이다. 이후 같은 통합 화면과 footer 소유자 구조로 확장할 수 있다.
- 매우 작은 화면에서는 게이지와 긴 기술/모습 목록의 내부 스크롤을 사용한다. 이번 시각 검증은 데스크톱 및 모바일 Chrome 기준이며 물리 패드는 연결하지 않고 표준 패드 입력을 모의 검증했다.

## 검증

- TypeScript, 프로덕션 빌드, CSS 구조 검사.
- 포인트·기술 후보와 기존 저장/성격/영입 관련 단위 테스트 8개.
- Chrome E2E 총 17개 통과(기존 메뉴 회귀 포함): 통합 설정, 기존 도감/출발 파티/필터/즐겨찾기/룰 전달, 상점·가방·TM·배틀 메뉴, 표준 패드 입력.
- 1280×900·1280×720 및 390×740·390×667 화면 경계를 확인했다.
- 통합 화면의 두 컬럼, 모든 기술 슬롯, Q/E와 좌우 포인트 조절·적용/취소·66 제한, 성격 축과 적용, 성별 전환/고정/무성, 보유 기술만 표시/중복 차단, 특성·테라 적용, 서버 저장 및 성장 포인트 차감, 커서 복원, footer 하나와 컨텍스트 복원, 모바일 화면 경계를 확인한다.
