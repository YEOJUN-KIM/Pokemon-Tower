# 배틀 UI 3차 정리 — 2026-10-20

2차의 수동 빌런 조우, 공통 PokemonSettings, 폼 변경 제한 및 X 설정 동작을 유지한다.

## 구현

- 레이드: 일반 이벤트와 같은 near/far 좌표를 사용한다. 플레이어는 좌측 하단, 실루엣은 우측 상단이다. 자동 진행과 별도 도전 버튼 대신 기존 메시지 확인을 사용한다. 키보드·클릭 중복 전송은 공통 one-shot guard와 기존 요청 잠금으로 차단한다.
- 패배: 제목과 `재도전 남은 횟수/실제 한도`, `도전 종료`만 표시한다. 한도는 구매한 실제 값이므로 1회 한도라면 1/1이다. 소진 시 재도전 버튼은 비활성화된다. 중복 배너·뒤쪽 다음 층 버튼을 제거했다. 기존 retry/finish-loss 정산 API를 연결한다.
- 재도전: 기존 상대 팀 텍스트 나열을 스프라이트·이름·타입·4개 기술 카드로 교체했다. 출전 팀 선택 카드에도 아군의 현재 기술 4개를 표시한다. 능력치 상세는 공통 포켓몬 설정에 그대로 둔다.
- 메시지: 문장별로 표시 컴포넌트를 새로 만들고 표시 문자열은 빈 값에서 시작한다. CSS 의사요소에 완성 문장을 넣던 구조를 제거했다. 타이핑 중 첫 Enter/Z/클릭은 현재 문장만 완성하고, 전체 표시 후 입력은 다음 단계로 진행한다. reduced-motion 사용자는 기존 접근성 정책대로 즉시 전체 문장을 읽을 수 있다.
- 전환: 재생 종료 때 최종 tower/battle 상태를 같은 업데이트에서 반영한다. 출전 준비 계산과 공통 모달 열기·포커스 이동은 페인트 전에 처리한다. 메시지의 run/floor/state 키도 함께 변경해 이전 문장을 재사용하지 않는다.
- 이벤트: 결과 설명을 메시지창에서 먼저 확인한다. 실제 지급 항목이나 선택 보상이 있을 때만 보상 팝업을 연다. 빈 상자·함정·순간이동은 메시지 확인 뒤 진행한다. 팝업은 보상 정보 행, 선택 카드, 받기 동작으로 구성하고 공통 footer만 사용한다.

## 원인 조사와 보유품 정책

조사: TowerStore.retry/createRetryBattle/input/complete/view, RunBag.view, run_item_bag, run_held_items, run_battle_items, run_reward_inventory 및 기존 retry/held-item 테스트.

기존 정책은 **현재 보유품을 유지하며 같은 상대/시드/층으로 재도전**하는 것이다. 전투 시작 직전의 전체 배낭을 되감는 정책이 아니다.

- 사용한 배틀 소모품·영양제는 복구하지 않는다.
- 미사용 도구, 남은 소모품, TM, 트레이너 장비는 Run에 저장한다. 재도전 함수는 이 테이블을 초기화하지 않는다.
- 새 전투는 현재 지닌 도구와 남은 battleItems를 새 스냅샷으로 읽는다. HP/PP/랭크 등 전투 임시 상태는 새 전투에서 초기화된다.
- 재사용 도구의 자연 발동은 장착을 유지한다. 실제 Knock Off 등의 도구 제거는 기존 전투 종료 정책을 유지한다.
- bag 상세는 select 상태에서만 내려온다. 전투 중/패배 상태에서 bag 필드가 없는 것을 전체 보유품 삭제로 취급하면 안 된다.
- 재도전만으로 전체 배낭이 삭제되는 현상은 이번 테스트에서 재현되지 않았다. 임의의 과거 배낭 복원은 넣지 않았다. 새 디스크 저장/재열기 테스트로 미사용 도구·장착품·TM·영양제·남은 배틀 아이템과 다음 전투 스냅샷을 검증한다.

화면 전환에는 페인트 후 effect로 모달을 열고 상태를 맞추던 중간 단계가 있었다. 이를 layout effect 및 최종 상태의 동시 반영으로 정리했다. 타이핑 초기화도 문장 키 단위로 분리했다. 보상 팝업은 기존 타이머 자동 열기를 제거하고 결과 확인 입력이 소유하도록 바꿨다.

## 보상 저장 시점

서버 계약을 유지했다. 일반 고정 보상은 결과 생성/승리/영입 등 기존 서버 처리 시점에 원자적으로 저장된다. 선택 보상은 persisted candidate ID를 검증한 선택 요청에서 지급하고 selected 상태를 저장한다. 팝업의 받기는 이벤트 완료 요청이다. 모든 보상을 최종 버튼에서 일괄 지급하는 새 계약으로 바꾸지 않았다. 이미 저장된 이벤트와 실패 후 재전송·새로고침에서도 기존 receipt와 선택 ID로 중복 지급을 방지한다. 결과 설명 확인은 클라이언트 표시 상태여서 새로고침하면 다시 읽을 수 있지만 재지급되지 않는다.

## 수동 확인 순서

1. 레이드 조우에서 플레이어/실루엣 구도를 보고 기다린다. 자동 진입하지 않는지 확인한다.
2. 타이핑 중 Z로 문장만 완성한 뒤 다시 Z로 진입한다. 클릭과 Enter를 함께 보내도 한 번만 시작하는지 확인한다.
3. 패배에서 실제 남은 횟수를 보고 재도전한다. 상대 카드와 출전 카드의 4개 기술을 확인한다.
4. 배낭의 미사용품·장착 도구·TM·남은 소모품을 확인하고 새로고침한다. 새 배틀에서 사용한 소모품이 되돌아오지 않는지 확인한다.
5. 빈 상자/함정은 결과 메시지만 읽고 진행한다. 보상 있는 상자는 메시지를 확인한 다음 팝업에서 받는다.
6. 선택 보상을 고르고 새로고침한 뒤 다시 받더라도 지급이 늘지 않는지 확인한다.
7. 영입 결과 → 이벤트 → 출전 준비와 순간이동 도착에서 이전 문장/출전 준비 팝업이 끼어들지 않는지 확인한다.
8. 출전 준비 및 정비의 X 설정, 폼 행 숨김, 저장 후 커서 복귀가 유지되는지 확인한다.

## 후속 키보드 수정

- 정비/재도전의 포켓몬 조정 목록에서 X로 설정을 열던 별도 단축키를 제거했다. 목록에서 Z/Enter는 포켓몬 설정 열기, X/Esc는 이전 메뉴로 돌아가기다. 하단 안내도 수정했다.
- 재도전 메뉴의 포켓몬 조정·배낭·출전 팀 선택은 가로 이동 그룹으로 지정했다. ←/→로 이동하며 ↑/↓는 옆 버튼으로 이동하지 않는다.
- 출전 팀 카드에서 X로 포켓몬 설정을 여는 기능은 유지한다.
- 1280/390 브라우저 회귀 6개에서 뒤로 가기/설정 열기/닫은 후 커서 복귀/좌우 이동/저장 및 폼 유지 검증. 빌드·타입·diff 검사 통과.

## 출전 준비 X 및 배낭 방향키 후속 수정

- 재도전 후 출전 팀 선택에 들어갈 때 첫 커서를 배틀 시작 버튼이 아닌 포켓몬 카드에 둔다. 카드에서 X로 공통 설정을 열고 닫으면 같은 카드로 돌아온다. 두 카드 사이 이동 후에도 각각 올바른 설정을 여는지 검사한다.
- 배낭 내부 버튼의 closest(horizontal/list) 탐색이 바깥 재도전 메뉴까지 올라가던 문제를 수정했다. 현재 열린 dialog 안에 있는 이동 그룹만 적용한다. 배낭의 ↑/↓ 선택 및 상세 항목 갱신과 바깥 메뉴의 ←/→ 이동을 함께 검사한다.

## 전용 도구 장착 대상 표시

장착 불가 대상은 공통 ItemTargetList에서 회색 배경·낮은 강조도·흑백 스프라이트로 표시한다. 배낭 및 구매 후 바로 장착 화면에 기존 장착 조건을 이용한 `장착 불가` 표시를 추가했다. 장착 가능한 포켓몬의 색상과 기존 키보드 제외 규칙을 유지한다. 리자몽나이트X에서 리자몽만 활성이고 나머지 카드가 비활성임을 1280/390에서 검증하고 모바일 이미지를 확인했다.
