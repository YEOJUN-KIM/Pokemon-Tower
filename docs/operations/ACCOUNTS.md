# 계정과 기존 저장 복구

첫 접속은 로그인 화면으로 이동한다. 로그인 성공 시 중간 계정 화면 없이 타이틀로 이동한다. 로그인한 브라우저는 30일 동안 로그인 상태를 유지하며 다시 접속하면 바로 타이틀로 이동한다. 로그아웃·쿠키 삭제·세션 만료 후에는 다시 로그인한다. 도감·배틀·설정·상점 주소도 비로그인 상태에서는 먼저 인증 화면으로 이동한다. 가입 완료 화면은 환영 문구·사용자 아이디·복구 키와 **게임 시작하기** 버튼 하나를 표시하며 버튼을 누르면 타이틀로 이동한다. 로그인 중 `/account`를 직접 열면 별도 계정 관리 화면 대신 타이틀로 이동하고, 허용된 `next`가 있다면 해당 화면으로 이동한다. 기본 해금은 1~9세대 스타팅 일반 최종 진화형 27종이며 배틀에는 3마리를 선택한다. 기존 도감·능력치·재화·진행 중인 도전을 유지하면서 기본 해금을 추가한다.

회원가입은 현재 게스트 저장을 계정에 연결한다. 다른 기기나 임시 주소가 바뀐 뒤에도 **같은 서버 DB에서** 같은 아이디로 로그인하면 이어서 플레이할 수 있다. 소리 설정도 로그인 계정에 저장한다. 회원가입 시 계정 복구 키를 한 번 표시하므로 복사해 안전하게 보관한다. 기존 저장 복구 코드 입력은 **복구 코드 입력하기**를 누를 때만 펼쳐진다. 아이디 형식 설명은 회원가입에만 표시한다.

비밀번호 찾기는 아이디·계정 복구 키 입력 → 새 비밀번호·확인 입력의 두 단계다. 첫 단계는 프론트 입력 단계 전환이며 서버에서 계정을 확인했다는 뜻은 아니다. 실제 키 검증·비밀번호 변경·키 교체·기존 세션 해제는 두 번째 제출에서 기존 reset API가 함께 수행한다. 완료 화면에서 새 키를 보관하고 게임을 시작한다. 이메일·소셜 로그인은 제공하지 않는다.

타이틀의 트레이너 이름은 클릭하지 않는 텍스트다. 설정의 배틀 탭은 배틀 옵션만 표시하며, 계정 탭은 계정 정보와 우측 로그아웃 버튼 하나를 표시한다. 로그아웃은 기존 API로 세션/쿠키를 정리한 뒤 로그인 화면으로 이동한다. DB schema와 인증 API 계약은 변경하지 않았다.

## 인증·설정 UX 검증 (2026-10-24)

`account-screen.tsx`의 로그인된 계정 중간 화면과 복구 키 다운로드 버튼을 제거했다. 복구 키는 완료 화면에서 선택·복사할 수 있고, 유일한 버튼은 게임 시작하기다. 로그인·가입·비밀번호 찾기는 같은 카드/입력·버튼 높이를 사용하며 Enter로 제출한다. `/account`는 인증 진입점으로 남기고 로그인 상태에서는 서버에서 이동한다. 별도 계정 관리 페이지는 추가하지 않았다.

격리 DB와 Chrome의 1280px/390px 화면에서 가입 완료의 단일 버튼, 게스트 저장 연결, 30일 쿠키, 다른 기기 로그인, 로그아웃, 복구 코드 펼치기, 두 단계 비밀번호 변경과 키 교체, 타이틀 텍스트, 설정의 우측 로그아웃 및 키보드 이동을 확인했다. 인증·설정·튜토리얼 대상 E2E 13/13, 관련 단위 테스트 25/25와 CMD 3/3, 타입·CSS·workspace 검사, production build가 통과했다. 개인 플레이어 DB와 테스트 DB는 분리했다.

더 넓은 playtest 파일 실행에서는 요청 범위 밖 5건(4배 연출 시간, 영입 표시 문구 2건, 알 결과, 소리 버튼 색상)이 현행 화면과 기존 기대값 불일치로 실패했다. 해당 게임 기능은 이번 작업에서 수정하지 않았다. 대상 E2E 결과와 구분하며 전체 E2E가 통과했다고 간주하지 않는다.

## 원래 로컬 저장 가져오기

운영자가 로컬 DB에서 원래 플레이어를 확인한 뒤 다음 절차로 선택한 저장만 가져온다. 여러 플레이어의 데이터를 덮어쓰지 않는다.

1. `TOWER_DB_PATH`를 원본 DB로 지정하고 `node scripts/export-save.mjs 플레이어ID앞10자리` 실행. `.data/original-save.json`에 해당 플레이어의 도감·육성·재화·전체 도전과 전투 기록을 내보낸다.
2. 대상 서버 DB 백업. 테스트 서버에는 `docker compose -p tower-preview --env-file .data/preview.env -f compose.yaml -f compose.preview.yaml exec -T game node scripts/backup-db.mjs` 사용.
3. JSON을 서버 `/tmp/original-save.json`으로 복사하고 `node scripts/import-save.mjs /tmp/original-save.json /data/original-save-recovery.txt` 실행.
4. 복구 코드 파일을 본인에게만 전달하고 회원가입의 **기존 저장 복구 코드**에 입력. 가입하면 그 저장을 연결한다.

저장 복구 코드는 7일 유효하고 한 번만 사용할 수 있다. 계정 비밀번호 복구 키와 용도가 다르다. 원본 JSON에는 플레이 데이터가 있으므로 공개 폴더·Git에 넣지 않는다. 이미 계정에 연결된 저장은 추가 계정으로 가져올 수 없다.

## 운영 구조

현재 지원 SQLite 스키마는 **47**이며 계정·세션·복구 코드·소리 설정을 저장한다. 계정 기능이 처음 추가된 버전과 현재 지원 스키마를 혼동하지 않는다. 저장 구조의 기준은 [DB 안내](../engineering/DATABASE.md)다. 비밀번호는 개별 salt를 사용하는 scrypt 파생값으로 저장하며 원문을 저장하지 않는다. 로그인 쿠키는 HttpOnly/SameSite=Strict이며 HTTPS 배포에서는 Secure다. 세션 토큰은 DB에 해시만 저장한다. 로그인·복구 시도 횟수를 제한한다. 가입 후 예전 게스트 쿠키만으로 계정 저장에 접근할 수 없다.

업데이트 전 DB 백업을 보관한다. 구버전 프로그램에 새 DB를 그대로 연결하지 않는다. 되돌릴 때에는 해당 프로그램 버전의 백업도 함께 복원해야 한다. 개인 임시 터널로 공유할 때도 실제 HTTPS 주소와 DB 백업을 확인한다.
