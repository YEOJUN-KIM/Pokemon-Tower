# 개발 이어받기

기준: 2026-10-16. 이 파일은 다음 작업의 시작점만 담고, 과거 완료 로그는 누적하지 않습니다.

1. [현재 상태](STATUS.md), [다음 계획](current/ROADMAP.md)을 읽습니다.
2. [폴더와 파일 관리](engineering/WORKSPACE.md)에서 수정 위치와 결과물 보관 기준을 확인합니다.
3. 게임 규칙은 [게임 안내](gameplay/README.md), 특정 변경 근거는 [보고서 목록](../artifacts/README.md)에서 찾습니다.

현재 실제 로컬 저장은 환경 설정의 `TOWER_DB_PATH`를 사용합니다. 이 PC에서는 `.data/dev-migrated.sqlite`이며 함께 사용하는 WAL/SHM 파일을 임시 파일로 취급하지 않습니다. 미커밋된 기능 변경이 있으므로 작업 전 `git status`를 확인합니다.

보고서는 AI·밸런스·팀 샘플로 분류했습니다. NPC 생성기의 입력은 `scripts/data/npc/`, 리뷰용 표는 `artifacts/reports/npc/`에 있습니다. 과거 실험의 소스 해시는 당시 버전의 기록이며, 경로 정리 후 현재 소스와 같다는 뜻이 아닙니다.

빠른 검사: `pnpm typecheck`, `pnpm check:css`, `pnpm check:workspace`. 브라우저 검증 전에는 빌드를 수행합니다. 테스트별 로그인 준비와 JSON import 지원은 [실행 안내](operations/SETUP.md)를 확인합니다.

현재 코드의 저장 스키마는 33입니다. 이 PC의 개발 DB는 아직 v32이며, 다음 로컬 서버 시작 때 v33으로 이전됩니다. 터널용 Docker DB는 v33입니다. `run_trainer_equipment`에 다이맥스밴드·테라스탈오브를 함께 저장하며, 배틀의 `trainer_equipment`는 생성 시점 장비 배열을 고정합니다. NULL인 기존 배틀은 종전 도구·테라권 규칙을 유지합니다. NPC 샘플의 트레이너 장비 분리는 아직 적용하지 않았습니다.

v31은 v29·v30에서 자동 이전된 장비를 구매 영수증 기준으로 정정합니다. 과거 배틀 스냅샷은 보존하지만 화면과 신규 행동은 현재 보유 장비로 제한합니다.

포켓몬에게 장착하며 산 과거 밴드는 트레이너 장비 구매로 인정하지 않습니다. 포켓몬 대상이 없는 트레이너 장비 구매 영수증만 인정합니다.

## 현재 작업의 핵심

- [이벤트](gameplay/EVENTS.md)는 상자·브리더 선물·여행 상인 3종이다. 전체 등장 10%, 종류 비중 50/30/20, 다음 두 층 재등장 방지. 층을 소모하지 않으며 DB의 종류·선택·보상을 복구한다.
- 이벤트 요약은 메시지창 바로 위 왼쪽의 작은 창이다. 그림·이펙트는 필드에 두고 설명·선택은 아래 전체 폭을 사용한다. 선택 후 요약을 없애고 이벤트 중 포켓몬 발판을 숨긴다.
- 개인 실행은 루트의 `포켓몬타워 실행.cmd` 하나로 연다. WinForms 창에서 서버 켜기/끄기·상태·게임 열기·주소 복사를 제공한다. QR·고정 주소·유료 호스팅은 적용하지 않았다.
- 실행기는 기존 Docker `tower-preview` 볼륨을 유지한다. `.env.local`의 개발 DB와 자동 동기화하지 않는다. 이미지 업데이트 전 볼륨 DB를 백업하며 터널 시작 시각 이후 로그에서 새 주소를 읽는다.
- 배틀 현재 대화창·지난 기록 분리, 빠른 배속의 메시지 읽기 시간, 기술배치 무료 자동 저장, 이로치 등장 및 최종 클리어 전환을 보완했다.
- 검증·패키지 기록은 [이벤트와 개인 실행 검증](../artifacts/reports/changes/NONCOMBAT_EVENTS_RELEASE.md)에 있다. 새 컴퓨터로 갈 때에는 [이전 안내](operations/COMPUTER_MOVE.md)에 따라 개인 저장 ZIP도 별도로 챙긴다.
