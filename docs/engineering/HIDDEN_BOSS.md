# 히든보스 확정 이벤트와 전투 재생

히든보스가 있는 테마의 마지막 챔피언을 격파하면 정비·영입 화면을 거치지 않고
`hidden-boss` Run Event → 회복 안내와 `!` → 조우·등장 메시지를 확인한 뒤 전투로 연결한다.
현재 해당 테마는 관동·성도·하나·팔데아이며, `towerThemes`에 `hiddenBoss: true`로 명시했다.
각 테마의 `champion`을 실제 격파한 50층/100층에서만 발생한다. 상대는 같은 테마의 기존 `final` 샘플을 재사용한다.

## 이벤트와 저장

- `hidden-boss`는 일반 weighted 추첨의 weight가 0인 확정 이벤트다. 챕터 챔피언 승리 transaction에서 직접 생성한다.
- 다른 무작위 이벤트를 함께 추첨하지 않는다. 일반 이벤트 발생률·쿨다운과 별개인 챕터 완료 조건을 적용한다.
- DB v45의 `hidden_boss_events`에 파티·seed·룰·초상화·기믹·보상 snapshot과 현재 battle ID, 지급 receipt를 보관한다.
- 조직 캠페인과 히든보스가 같은 `trainer-event-battle.ts` snapshot 생성 함수를 사용한다.
- 챔피언 승리 보상은 기존대로 한 번 지급한다. 일반 영입 단계는 건너뛰고 그 층의 클리어 수를 한 번 기록한다.
- 히든보스는 별도 이벤트 전투다. 승리하면 이벤트 보상을 한 번 지급한다. 확인 후 50층은 51층으로, 100층은 도전 완료로 전환한다.
- 원래 출전하던 3마리를 사용한다. 새 전투 시작 규칙에 따라 HP·PP·상태가 회복된다. 소모된 지닌 도구나 사용한 아이템을 복제하지 않는다.
- 재시도는 기존 런 retry 한도를 사용하며 상대와 보상을 다시 뽑지 않는다.
- 예전 저장에서 이미 히든보스 정비 대기 상태라면 서버 상태 조회 시 확정 이벤트로 연결한다.

## 전투 마지막 턴

이전에는 특수 전투 승리 후 서버가 `select` 상태로 이동하면서 action 응답의 `battle`이 null이 되어
클라이언트가 마지막 타격·기절 로그를 재생하지 못했다.
`TowerService.action`은 해당 action으로 끝난 저장 battle view를 응답에 포함한다.
클라이언트는 재생 중 결과/이벤트를 표시하지 않고 마지막 타격과 기절을 마친 뒤 결과 이벤트를 연다.
일반 GET 상태 조회는 끝난 특수 전투를 다시 시작하지 않는다.

## 로켓단 화면 조정

- 기습은 시설 배경을 덮어씌우지 않는다. 이벤트가 발생한 층의 맵 배경을 조우·전투·보상 동안 유지한다.
- `!` 연출은 기본 1.2초, 빠른 배속에서도 최소 0.8초다. reduced-motion에서는 움직임을 제거한다.
- 기습 승리 후 상대 초상화나 시설 배경을 다시 표시하지 않는다.
- 간부/보스 안내는 짧은 두 줄로 표시한다. `GameDialogue`에서 실제 줄바꿈을 보존한다.
- 예전 snapshot의 긴 빌런 대사를 전투 입장 때 다시 표시하지 않는다.

## 검증

`tests/hidden-boss-events.test.ts`는 테마/마지막 챔피언 조건, 관동·성도 50/100층,
자동 진입을 위한 준비 상태, 원래 출전 팀 회복, 보상/클리어 exact-once, 재접속, 재시도, v44→45 migration을 검증한다.
`tests/rocket-campaign.test.ts`는 실제 마지막 action 응답에 타격·기절·승리 로그가 포함되는지 검증한다.

`e2e/hidden-boss-events.spec.ts`는 실제 챔피언 마지막 타격 후 영입/정비/일반 승리 팝업 없이
`!` 이벤트와 자동 히든보스 전투가 이어지는지 데스크톱 50층, 모바일 100층에서 확인한다.
`e2e/villain-campaign.spec.ts`는 기습 배경/속도/줄바꿈과 간부·비주기의 마지막 기절 연출 후 보상 순서를 확인한다.

로켓단 및 히든보스 브라우저 테스트 **8/8 통과**.
타입 검사, Next.js 프로덕션 빌드, CSS 및 워크스페이스 검사도 통과했다.
