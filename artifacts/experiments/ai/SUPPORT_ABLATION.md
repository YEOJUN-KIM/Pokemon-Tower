# 벽·교체·랭크업·피해 추정 분리 비교 · 2026-10-10

지난 v10 후보에서 한꺼번에 바꾼 조건을 분리했다. 게임 상대 AI·기존 실험 정책·난이도는 유지했다. 정책은 상대의 숨은 세팅을 읽지 않고 자기 팀과 공개 배틀 정보만 사용한다. 모델 가중치를 학습한 작업은 아니다.

## 비교한 변경

각 변형은 동결된 v9를 기준으로 아래 묶음 하나만 바꾼다. 이전 v10의 수면 중 마무리 분류·트릭룸 추가 제한·혼합 공격 위협 추정은 포함하지 않는다.

- 벽 보호 판단: 현재 아군의 예상 최대 피해가 벽으로 15% 이상 감소할 때만 벽을 근거로 교체/랭크업한다. 벽을 처음 설치할지 정하는 로직은 그대로다. 보호 여부는 근사치라 모든 상대 기술이나 교체받는 아군의 위협을 완전히 표현하지 않는다.
- 교체 조건: 남은 벽3턴, 받는 피해25% 미만, 진입+두 번의 피해 후 체력 여유, 얼음/물리 화상 제한. 설치·랭크업·피해 추정은 그대로.
- 랭크업 조건: 받는 피해25% 이하, 두 번 버틸 체력, 물리 화상 제한, 이미 큰 공격 피해를 줄 수 있으면 공격 우선. 설치·교체·피해 추정은 그대로.
- 피해 추정: 기본 가정 위력80→100, 공격 종족값+20→(종족값+52)×1.1. 이것도 가정이며 상대의 실제 능력치를 읽지 않는다. 나머지 문턱은 그대로.

## 개발용 비교와 후보 선택

이미 결과를 본 이전9코스를 개발용으로 명시했다. 6팀×11층×9코스×기본/테라/개판×5정책 = 8,910배틀. 기존 v9를 다시 돌린 전체 행동과 공개 프로토콜이 지난 기록과 일치했다(시각 메타데이터 제외).

| 변형 | 개발용 승수 | v9 대비 |
|---|---:|---:|
| 기존 벽 활용 v9 | 1688/1782 | 0 |
| 벽 보호 판단만 | 1689/1782 | 1 |
| 교체 조건만 | 1687/1782 | -1 |
| 랭크업 조건만 | 1679/1782 | -9 |
| 피해 추정만 | 1676/1782 | -12 |

실행 전 정한 총 승수/고정 동률 순서로 후보 하나만 골랐다. 선택은 **벽 보호 판단만**. 개선 폭은 1승으로 작아 우월성의 근거로 삼지 않았다. 유리한 팀/층만 골라 집계하거나 결과를 본 뒤 조건을 튜닝하지 않았다. 후보 선택과 구현/하네스/코스 해시는 artifacts/experiments/ai/support-ablation-selection.json 및 단계별 manifest.json에 저장했다.

## 새 코스 독립 배틀

후보를 고정한 뒤 새 지역별9코스를 생성했다. 개발용과 과거 실험 코스의 ID가 모두 겹치지 않는다. 6팀×11층×9코스×5룰×기존/후보 = 5,940배틀. 기존처럼 완전 육성된 고정팀에 매번 HP를 회복하고 벽 요원은 빛의점토를 가진다. 개별 배틀 성공률이지 등반 성공률이 아니다. 메진 룰은 이 표본의 실제 메가 사용이 적거나 없으면 메가 활용 평가로 해석할 수 없다.

| 룰 | 기존 v9 승수 | 후보 승수 | 같은 상대에서 개선 / 악화 |
|---|---:|---:|---:|
| 기본 | 557/594 | 555/594 | 0 / 2 |
| 메진 | 557/594 | 555/594 | 0 / 2 |
| 다맥 | 556/594 | 554/594 | 0 / 2 |
| 테라 | 561/594 | 559/594 | 0 / 2 |

새 코스 독립 배틀에서 후보가 기존보다 10승 적어, 개발용 개선이 재현되지 않았다. 후보를 기본 정책으로 승격하지 않는다.

룰 간에 같은 팀/코스/층/시드를 공유하므로 합계의 모든 배틀을 독립된 증거로 취급하지 않는다. 지역별1코스씩인 작은 표본이고 새 코스 결과를 본 뒤부터는 이 코스도 후속 개발에 사용한 검증 자료가 된다. 같은 시드에서 정책 변경 후 난수 소비와 상대 선택이 달라질 수 있어, 단일 배틀의 한 행동만 원인이라고 단정하지 않는다.

## 영입·상점 포함 등반

같은 새 코스에서 6출발팀×9코스×3룰×2정책 = 324등반, 16,398배틀. 돈/상점/무료 리롤/기술머신/비타민/배틀 소모품/영입/역할 기반 파티 재선택을 적용했다. 처음부터 빛의점토를 주지 않고 구매해야 한다. 실패 시 종료한다.

각 칸: 평균 성공 층 / 50층 통과 / 100층 완주.

| 룰 | 기존 v9 | 후보 |
|---|---:|---:|
| 기본 | 53.3 / 27/54 / 16/54 | 53.9 / 27/54 / 16/54 |
| 테라 | 48.4 / 24/54 / 13/54 | 49.3 / 24/54 / 14/54 |
| 개판 | 46.7 / 22/54 / 10/54 | 47.4 / 22/54 / 11/54 |

기존 등반 하네스의 층마다 회복·최대6마리 수집·자동 기술 정비를 유지한다. 실제 사람의 선택이나 모든 영구 도감 육성 지출을 재현하지 않는다. 독립 배틀과 등반은 같은 코스이므로 별도의 검증 표본이 아니다. 등반 중 영입으로 출발 벽 요원이 빠질 수 있으며 영입/파티 변화도 플레이 정책에 따른 경로 차이의 일부다. 단계별/지역별/조합별 결과와 짝 비교는 감사 JSON에 있다.

## 데이터와 검사

개발용 74,848개, 검증용 52,015개 행동 직전 기록을 추가했다. 입력은 observation/context, 행동과 이유는 라벨, outcome은 미래 결과이므로 입력에 넣지 않는다. 재생 파일의 상대 전체 팀은 정책 입력으로 사용하지 않는다. 같은 courseId의 모든 룰·팀·층·정책을 같은 학습/검증 그룹에 둔다.

분리 조건/기존과의 대조/합법 마무리/공개 입력 경계/벽 잔여 턴 테스트5개 및 관련 기존7개 통과. TypeScript 검사 통과. 전체 데이터에 합법 선택·순서·승패 합계·교체 제한·돈 수지·층 순서·실패 종료를 검사했다. 대표 62배틀을 재생해 승패/턴/행동을 대조했고 독립 배틀은 전체 공개 프로토콜도 대조했다. 기존 정책·실제 상대는 변경하지 않았다.

실행: node scripts/run-support-ablation.mjs dev, 이어서 validate. --resume는 같은 해시/완성된 기록만 재사용한다. 새 validate 코스 파일이 이미 있으면 재실행은 같은 코스를 쓰며 덮어쓴다. 새 검증을 하려면 새 이름의 코스·실험 경로로 원본을 보존해야 한다. 감사: node node_modules/tsx/dist/cli.mjs scripts/audit-support-ablation.ts dev 또는 validate. 보고서: node scripts/write-support-ablation-report.mjs.

지금 근거로 교체/랭크업을 일괄 제한하거나 실제 상대를 강화하지 않는다. 다음 후보는 일괄 문턱 강화보다 공개된 실제 피해와 상대 교체 후 필요한 벽을 반영하는 방향으로 검토하되, 새 검증 코스를 별도로 확보해야 한다.
