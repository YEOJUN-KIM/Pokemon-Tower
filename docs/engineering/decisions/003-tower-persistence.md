# ADR 003 — 타워 흐름, SQLite 저장과 배틀 복구

> 초기 의사결정의 과거 기록입니다. 아래 단계 수·제약·미구현 항목은 작성 당시 상태이며 현재 사용 안내가 아닙니다. 현재는 [STATUS](../../STATUS.md), [구조](../ARCHITECTURE.md), [DB](../DATABASE.md)를 따릅니다.

날짜: 2026-10-04. 상태: 로컬 7종·3층 검증 구간에 채택.

## 결정과 이유

현재 환경에서 PostgreSQL·Docker 명령을 찾지 못했다. 첫 게임 흐름을 추가 설치 없이 검증하기 위해 Node.js 24의 내장 SQLite를 사용한다.
관계형 스키마와 트랜잭션을 실제 구현하며 SQL을 TowerStore에 모아 웹과 엔진을 분리한다.
PostgreSQL·Prisma는 공개 서비스 단계의 후보로 유지한다. 이를 이미 사용 중이라고 문서화하지 않는다.
동기 SQLite와 단일 Node.js 엔진 프로세스는 로컬 개발용 선택이다. 다중 서버 운영과 고부하 동시성은 후속 검증 대상이다.

## 임시 게임 규칙

- 7종: 리자몽·거북왕·이상해꽃·피카츄·갸라도스·잠만보·윈디.
- 최초 3종은 스타팅 최종 진화형. 초기 3종과 진화 정책이 최종 확정된 것은 아니다.
- 3층 검증 구간, 보상 100/150/200원. 마지막 승리 후 영입 선택을 마치면 클리어.
- 선택한 순서로 출전, 같은 종 중복 선택/영입 금지.
- 도전 시작에 해금 종 중 3마리, 이후 보유 최대 6마리에서 출전 3마리.
- 층 사이 HP·PP·상태이상 완전 회복. 도중 영입은 현재 고정 세팅 사용.
- 실제 영입한 종만 영구 해금. 영입 생략 가능, 이미 해금했어도 현재 미보유면 영입 가능.
- 보유 6마리에서는 기존 멤버를 지정해 교체. 교체로 빠진 종의 영구 해금은 유지.
- 돈과 도감은 패배·도전 종료 후에도 유지. 무승부는 승리 보상을 주지 않고 도전 종료.
- 세팅 구매/변경 API는 아직 없다. 클라이언트가 임의 세팅을 제출할 수 없다.

## 상태 전이

```text
로비 → 팀 선택 → battle
                  ├─ 패배/무승부 → lost → 새 도전
                  └─ 승리 + 보상 트랜잭션 → recruit
                                            ├─ 영입/생략 → select → 다음 층 battle
                                            └─ 마지막 층 → cleared → 새 도전
진행 중 → 자발 종료 → abandoned → 새 도전
```

영입 완료와 다음 층 증가를 한 트랜잭션으로 묶는다. 이미 처리된 영입 요청은 409로 거부한다.
진행 중인 도전이 있으면 새 도전 생성은 거부한다. 종료 단계에서의 새 도전 클릭은 새로운 도전을 의미한다.

## DB 무결성

- players/unlocks는 영구, runs/members/battles/actions는 도전 데이터다.
- 부분 유니크 인덱스로 플레이어별 활성 도전 1개를 보장한다.
- rewards.battle_id 기본키로 경기당 보상 1회를 보장한다.
- 완료 로그 저장·보상 원장 삽입·돈 증가·영입 단계 전환은 BEGIN IMMEDIATE 트랜잭션으로 처리한다.
- 중간 실패 시 모두 롤백한다. 같은 완료 콜백은 완료 상태 확인 후 아무것도 지급하지 않는다.
- members는 슬롯 0~5와 같은 도전 내 종 유니크 제약을 가진다.
- 모든 입력 SQL은 바인딩한다. 서버 엔진만 완료 콜백을 호출하며 HTTP에서 승자/지급액을 받지 않는다.

## 복구 방식

배틀 시작 때 양쪽 팀·시드·엔진 버전·포맷·AI 버전을 저장한다.
각 합법 입력은 actions에 먼저 커밋하고 엔진을 진행한다.
프로세스 재시작 시 초기 배틀을 만들고 저장된 사람 행동을 순서대로 재생한다. 규칙 AI는 동일 버전에서 결정적으로 재계산한다.
완료 경기에는 관측·양쪽 행동·결과가 담긴 전체 로그와 공개 화면 상태를 저장한다.
마지막 행동 저장 후 승리 확정 트랜잭션 전에 종료되어도 재생 후 보상을 한 번만 지급한다.
엔진·AI 버전이 다르면 복구를 거부한다. 규칙 AI를 바꿀 때 AI_VERSION을 반드시 갱신한다.

## 게스트 식별과 제한

HttpOnly·SameSite=Strict 쿠키의 무작위 256비트 토큰으로 소유권을 확인하고 DB에는 SHA-256 키를 저장한다.
계정 로그인이 아니므로 쿠키 삭제·다른 브라우저에서 기존 저장으로 이동하는 기능은 없다.
로그인과 저장 이전, 운영 DB·백업·마이그레이션 정책은 공개 배포 전 재검토한다.
