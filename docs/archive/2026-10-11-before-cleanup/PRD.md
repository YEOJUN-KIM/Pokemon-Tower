# PRD — Pokémon Tower

최종 갱신: 2026-10-10. 상태: 로컬 MVP 구현·확장 중.

## 목적

팀 편성, 턴제 싱글 배틀, 타워 진행, 포켓몬 수집과 영구 성장을 갖춘 웹 게임을 만든다.
주목적은 일반 웹·백엔드 개발 취업용 포트폴리오다.
화면 제작뿐 아니라 서버 검증, 관계형 데이터 모델, 트랜잭션, 보상 중복 방지,
진행 복구와 테스트를 설명할 수 있는 프로젝트를 목표로 한다.

원본: [기획 초안](../pokemon-tower-plan.md). 개발 상태는 [로드맵](ROADMAP.md)과 [개발 로그](DEVLOG.md)를 따른다.

현재 구현은 **607종·50층 타워**다. 팀 선택·보상·영입·영구 도감·성장 포인트·서버 재시작 복구와 타이틀·설정·승패 표시를 연결했다. 개체값 수집·능력 포인트·성격·특성·기술배치, 5층 강화 상점, 영입 없는 기술 저장, 독립 키보드 선택 커서를 지원한다. 일반·엘리트·혼합 샘플과 지우 등장 뒤 Z 확인으로 배틀을 시작한다. 새 도전은 성도 테마의 관장·사천왕·40층 목호·50층 레드를 배치하며 대표1마리와 원작 후보 파트너2마리를 선택한다.
초기 저장 결정은 [ADR 003](decisions/003-tower-persistence.md), 현재 화면은 [UI_FLOW](UI_FLOW.md), 확장 데이터와 검증 한계는 [콘텐츠 기록](CONTENT.md)을 따른다. 5층 상점에는 최대 4개의 기술머신을 등급별 100~1,000코인에 판매하며, 종별 영구 기술 수집과 이번 도전 장착을 지원한다. 기술머신 47종의 등급·층별 확률 추첨을 적용했다. 메가·다이맥스는 실제 효과/연출을 구현했다. 테라·Z·고급 교체 AI·100층은 후속 작업이다.

## 사용자 경험과 요구사항

개발 우선순위(2026-10-04): **타이틀 → 설정 → 종·층 확장 → 도감 → 배틀 개선**.
이 우선순위는 초기 기록이다. 현재 영구 성장과 임시 네임드·등장 연출까지 연결했으며 후속 순서는 ROADMAP을 따른다.
설정의 첫 범위는 브라우저별 음소거·효과음 크기와 게스트 저장 안내다. 로그인과 기기 간 연동 방식은 미정이며 현재 구현으로 간주하지 않는다.
타이틀의 게임 시작/이어하기는 저장을 지우지 않고 배틀룸으로 진입한다. 새 도전 생성은 기존 서버 검증을 따르는 팀 선택 이후에만 한다.

1. 로비에서 영구 도감, 보유 돈, 해금된 세팅을 확인한다.
2. 기본 포켓몬으로 시작하며, 도전 시작 전 세팅과 출발 포켓몬 3마리를 선택한다.
3. 도전 중 최대 6마리를 보유하고, 매 배틀에 출전할 3마리를 선택한다.
4. 1대1로 대면하는 턴제 배틀을 진행하며 기술 또는 교체를 선택한다.
5. 승리하면 돈을 받고 상대 포켓몬 중 1마리를 영입하거나 기존 멤버와 교체한다.
6. 패배 또는 도전의 최종 층(새 도전50층) 클리어로 도전을 종료하고 다시 도전한다.
7. 도감에 해금한 종은 다음 도전에서 사용할 수 있다.
8. 영구 성장 포인트로 능력 포인트·성격·특성 등의 세팅을 조정한다. 개체값은 최초 6Z에서 영입한 같은 종의 더 높은 값을 능력치별로 누적한다. 능력 포인트는 합계 66·능력치별 32이며 획득/소비 방식은 재검토할 수 있다. 이로치 성장 요소는 계획이다.
9. 영구 세팅 변경은 새 도전에 적용한다. 도전 중에는 영입 기술을 즉시 장착하는 별도 흐름을 지원한다. 타워 코인과 영구 성장 포인트를 분리하고 층 사이에는 HP·PP·상태이상을 전 회복한다.

## MVP 범위

- 초기 20종에서 현재 일반 도감607종으로 확장한50층 싱글플레이. 가능한 한 2D 도트, 레트로 글꼴·테마, 키보드/마우스/터치 조작.
- 팀 선택 → 배틀 → 보상 → 영입 → 다음 층 → 종료·재도전.
- 영구 도감·돈·최소 세팅 구매·진행 저장.
- 높은 층에서 더 나은 상대 조합과 AI 판단. 처음에는 상성·예상 데미지 중심.
- 규칙 AI를 학습 AI로 교체할 인터페이스와 화면 없는 실행 경로.

## 특수 기믹

- 현재 메가진화47종·다이맥스와 실제 효과/변신 연출을 지원하며 각 진영 둘을 합쳐 배틀당1회 사용한다. 상대도 같은 제한을 적용한다.
- 테라스탈·Z·거다이맥스 전용 형태는 후속 기획이다. 테라는 도감에서 타입을 지정하고 별도 테라권 칸·팀당1마리 장착, 에픽1회용/레전더리재사용형을 구상했다.
- 테라·Z까지 하나의 공통 사용 횟수로 묶는 안은 아직 확정하지 않았다. 구체적인 가격·상품·발동UI·상대 배정은 구현 전에 정한다.
- [현재 기믹](BATTLE_GIMMICKS.md)과 [로드맵](ROADMAP.md)을 따른다.

## 신뢰성과 완료 기준

- 서버가 행동·승패·돈·영입·해금을 검증한다.
- 같은 승리 보상 요청을 반복해도 지급은 한 번이다.
- 구매의 돈 차감과 해금은 함께 성공하거나 함께 취소된다.
- 미해금 포켓몬, 허용되지 않은 세팅, 도전 중 세팅 변경을 거부한다.
- 영구 데이터와 현재 도전 데이터를 분리한다.
- 초기 조건·시드·엔진 버전·행동·결과를 저장하고 같은 환경에서 재현한다.
- AI에는 자기 정보와 그 시점의 상대 공개 정보만 제공한다. 상대의 현재 입력과 비공개 세팅은 제공하지 않는다.
- 새로고침·서버 재시작 이후 합의한 저장 지점으로 복구한다. 초기 목표는 마지막 저장된 턴이다.
- 종·팀·층·이벤트를 데이터로 추가할 수 있다.

## 미정 사항

최종 세대별 테마와 네임드 후보, 코스트, 성장 포인트 경제·세팅 가격 재조정, 기술머신 상점 구성, 특수 기믹 제한, 계정·인증·배포 방식은 미정이다. 현재 레벨·개체값·회복·영입·정산 규칙은 구현된 임시 규칙이며 UI_FLOW와 CONTENT를 따른다. 초기 가정은 [기술 결정 기록](decisions/001-initial-scope.md)에 이력으로 남긴다.

## 후속 확장

금전 이벤트, 전설 조우, 희귀 교환, 관장 등 네임드 NPC 조우,
교체·상태이상·날씨 전략, 모방학습·강화학습.
복잡한 인프라, 마이크로서비스, 학습 AI는 첫 MVP에 넣지 않는다.


## 2026-10-10 상점 경제 요구사항

도구/TM은 구매한 자리까지 전체 유료 리롤하며 이미 보유한 상품은 유지한다. 소모품8종 중3종과 영양제6종 중4종은 저장 추첨하고 리롤하지 않는다. 영양제는 한 포켓몬의 도전 전용 추가 포인트다. 가격은 [경제 검증](SHOP_ECONOMY_50.md)을 따른다. 성장 포인트 리롤권/상품 제외와 영양제 히든 상점은 현재 구현하지 않은 기획이다.
