# 프로젝트 문서

새 도전은 **1~9세대 지역 테마 중 하나를 무작위로 선택**해 50층 동안 유지한다. 관장·사천왕급·챔피언·빌런 조직은 그 테마를 따른다. 기존 성도 및 테마 없는 저장은 이전 배치를 유지한다. 포켓몬의 출신 세대는 제한하지 않는다. 상세는 [세대 테마](REGIONAL_THEMES.md)를 따른다.

이 폴더는 사용자와 다른 사람이 프로젝트의 진행 상황·구현 수준·기술적 선택을 읽을 수 있도록 관리한다. 포트폴리오 설명의 근거로 활용하며 Markdown 설명 문서를 중심으로 관리하고 일부 리소스 출처 JSON을 함께 보관한다.
원본 구상은 [pokemon-tower-plan.md](../pokemon-tower-plan.md)에 보존한다.

최종 문서 갱신: 2026-10-10. 현재 구현은 612종·50층이며, 최근 변경은 1~9세대 랜덤 지역 테마·네임드105개 추가·지역별 빌런 조직, 공개 정보 기반 상대 교체 AI(v6), 빌런 간부·보스/추가 보상/격파 후 종료, 테라스탈(팀 공용 소모권·도감 타입·결정 UI/연출), 메가·다이맥스와 2D 연출, 기술 타입/분류 아이콘, 임시 효과음, 도구·TM 전체 리롤, 랜덤 소모품 3종·영양제 4종과 50층 가격 조정이다. 영구 재화 상점 확장은 사용자 요청으로 보류했다. 100층은 계획이다. 현재 화면은 UI_FLOW, 검증 이력은 DEVLOG, 다음 작업은 ROADMAP을 기준으로 읽는다.

## 먼저 읽을 문서

1. [현재 진행 상황](STATUS.md): 지금 무엇을 할 수 있고 어디까지 검증됐는지.
2. [포트폴리오 정리](PORTFOLIO.md): 구현한 문제 해결·직접 만든 범위·시연 순서와 화면.
3. [로드맵](ROADMAP.md): 다음 작업과 미완성 목표.
4. [사용 흐름](UI_FLOW.md): 도감·배틀·영입·조작 방법.

다른 사람이 처음 볼 때는 STATUS와 PORTFOLIO만으로도 현재 수준을 파악할 수 있게 한다. 기술 검토가 필요하면 아래 상세 문서를 읽는다.

## 기록 원칙

- **요구사항:** 사용자가 정한 제품 방향. **임시:** 첫 실행을 위한 되돌릴 수 있는 선택.
- **계획:** 아직 구현하지 않은 기능. **구현:** 코드가 있는 기능. **검증:** 실제 실행으로 확인한 범위.
- 계획을 구현 완료로 표기하지 않는다. 테스트 명령과 결과를 개발 로그에 남긴다.
- 서로 다른 문서에 같은 세부 설정을 복제하기보다 담당 문서로 연결한다.
- 기능 변경 시 PRD·로드맵의 상태를 확인하고 개발 로그를 함께 갱신한다.
- 읽는 사람에게 의미 있는 결과·예시·한계를 먼저 설명하고 코드 경로나 검사 명령은 근거가 필요할 때 제시한다.
- 검사 결과 JSON·출처 메타데이터는 `artifacts/reports/`, 화면 캡처는 `artifacts/screenshots/`에 보관한다. 문서에는 결과를 요약하고 필요할 때 이미지를 연결한다. 원본 자료를 삭제하거나 재검사한 것처럼 날짜를 바꾸지 않는다.
- 외부 게임/리소스 조사 문서는 당시 조사 기록이며 현재 구현 수준은 STATUS를 기준으로 한다. decisions 폴더도 과거 선택의 이력이며 최신 기능 목록을 대신하지 않는다.

- [네임드 전투 구성](NAMED_TRAINER_BUILDS.md): 대표 포켓몬·챔피언 기술·중복 없는 도구, 추가 최종전과 특수 기믹 구상.
