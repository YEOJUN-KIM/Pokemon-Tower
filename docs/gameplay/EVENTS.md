# 이벤트와 보상 기획

기준: 2026-10-18. **미스터리 상자·브리더·여행 상인·도전자/Mirror·히든상점·Raid·순간이동·로켓단 캠페인·히든보스와 공통 보상 처리를 구현했습니다.** 브리더·여행 상인은 기존 동작을 유지합니다. 콘텐츠 보강과 후순위 후보는 [이벤트 콘텐츠 설계](EVENT_CANDIDATES.md), 알 규칙은 [알 종류와 부화](EGGS.md)를 따릅니다.

## Raid v1 · 정체불명의 강적

검은 실루엣과 희귀성 오라를 보고 도전하거나 지나갈 수 있습니다. 이름·타입·기술·구체적인 보상은 도전 전에 공개하지 않습니다. 추가 확인 없이 등장 연출과 전투로 이어집니다. 한카리아스는 기본 → 메가의 2단계, 뮤츠는 기본 → 메가X 또는 Y → 같은 메가 폼의 강화 상태로 3단계를 상대합니다. 다음 단계에는 초과 피해가 넘어가지 않으며, 전환 직후 보스가 추가 공격하지 않습니다.

승리하면 기존 영입 UI에서 기본 모습의 보스를 영입할 기회와 특별한 보상을 모두 받습니다. 영입을 건너뛰어도 특별 보상은 지급됩니다. 패배 후 다시하기는 같은 개체·X/Y 경로·이로치·보상을 유지합니다. 이벤트가 끝나면 해당 층의 일반 전투를 준비합니다. [설정·저장·확장·검증 보고](../engineering/RAID_EVENTS.md).

## 도전자 선택전의 희귀 Mirror 후보

Mirror는 별도 Run Event가 아닙니다. 새 공통 도전자 후보 3명을 생성한 뒤 **3%**로 최대 한 슬롯을 교체합니다. 내부 기반 NPC Sample과 세 후보의 클래스 중복 방지를 유지하고, Mirror의 표시 이름은 `???`로 숨깁니다. 외형은 플레이어와 같은 청록색 모자·노란 재킷의 정면이며 모자 아래 얼굴에만 좁은 그늘을 넣습니다. 상세창은 `어딘가 익숙한 기분이 든다.`와 `특별한 보상`을 표시하며 실제 보상은 숨깁니다.

직전 일반층의 실제 출전 3마리 `player_team`에서 종족·폼·성격·기술·도구를 복사하고 IV/EV만 기존 Elite 육성으로 대체합니다. 영양제/임시 스탯 보너스는 복사하지 않습니다. 원본 일반전을 찾지 못하면 일반 후보를 유지합니다. 후보 생성 시 팀·기믹·보상을 저장하므로 새로고침·패배 후 재도전·플레이어 기술/도구 변경으로 상대가 바뀌지 않습니다.

Mirror 승리는 영입 없이 Master급 가치의 **랜덤 보상 한 종류**를 줍니다. 초기 가중치는 일반 알 티켓 ×10:30, 슈퍼레어 티켓:15, 이로치 티켓:2, 성장 포인트 1,500P:30, 미보유 트레이너 장비:15, 1V:7, 6V:0.5, 이로치 변환:0.5입니다. 적격 장비/강화 대상이 없으면 1,500P 대체 보상을 저장합니다. 보상 종류를 선택하지 않으며 강화일 때만 현재 로스터 최대 6마리 중 적용 대상(1V는 능력치도)을 고릅니다. 이미 V/6V/이로치인 대상은 제외합니다. [전체 구현·풀·검증](../engineering/MIRROR_CHALLENGER.md)을 따릅니다.

## 현재 구현: 미스터리 상자와 기존 만남

현재 전체 등장률은 적격 일반층마다 **10%**, 통과 순서 쿨다운은 **2**입니다. `src/data/run-events.ts`의 `eventEncounterSettings`에서 관리합니다. v1 종류 비중은 상자 50 / 브리더 30 / 여행 상인 20입니다. v2에는 도전자 20, 히든상점 12, Raid 20, 포탈 10과 조건부 로켓단 단계 weight 100이 추가됩니다. 종류 weight는 현재 적격한 이벤트끼리만 정규화하며 전체 등장률과 다릅니다. 수동 QA 강제 등장/로켓단 전용 제한은 없습니다. 히든보스는 조건을 만족한 챕터 종료에서 확정 생성하므로 일반 추첨과 구분합니다. 상자 내부 결과는 legacyChestRewards/mysteryChestResults이며 이미 저장한 선택·보상은 유지합니다. [설정·조건·추가 절차](../engineering/EVENT_SYSTEM.md)를 따릅니다.

## 히든상점 · 수상한 상인

상품은 세로 목록에서 비교하고 현재 선택 상품의 설명·가격·상태는 우측 상세에서 확인합니다. 하단은 상인 대화 전용이며 공통 배낭을 열어 아이템을 사용할 수 있습니다. 1–5는 확인만, Z/Enter 또는 작은 구매 버튼은 구매, X는 나가기입니다. 모바일은 카드 터치로 확인한 뒤 구매 버튼으로 확정합니다. [히든상점 UI](../engineering/HIDDEN_SHOP_UI.md).

이벤트 ID는 `hidden-shop`입니다. 일반 전투를 대체하거나 층을 소모하지 않습니다. 상품 **4–5개**를 한 번 추첨해 저장하고, 코인·성장 포인트를 합쳐 **최대 2개** 구매합니다. 같은 상품도 이벤트마다 다른 결제 재화/가격으로 나올 수 있지만, 열린 상점은 새로고침·서버 재시작 후에도 그대로입니다. 구매하지 않고 나갈 수 있으며 나가면 이벤트가 종료됩니다.

| 상품 그룹 | 초기 가중치 | 수량 | 코인 가격 범위 | 성장 포인트 범위 |
|---|---:|---|---|---|
| 영양제 6종 | 32 | 1 | 400–700 | 80–150 |
| 기존 에픽 지닌 도구 | 20 | 1 | 1,500–2,500 | 250–450 |
| 기존 unique/epic TM | 20 | 1 | 1,200–2,000 | 200–400 |
| 일반 알 티켓 | 24 | 3 / 5 | 800–1,500 | 150–300 |
| 슈퍼레어 알 티켓 | 3 | 1 | 3,000–5,000 | 600–1,000 |
| 트레이너 장비 | 1 | 1 | 5,000–8,000 | 1,000–1,500 |

현재 모든 상품은 두 재화를 허용하고 각각 50%로 추첨합니다. 상품 ID는 중복되지 않고 같은 그룹을 뽑을 때마다 가중치를 0.25배로 줄입니다. 미보유·룰 적격 장비만 진열하고, TM은 현재 파티 중 새로 배울 수 있는 대상이 있어야 합니다. 이로치 알/티켓은 제외했습니다.

영양제와 TM은 공통 배낭에서 사용하며 영양제 총 3개 제한을 유지합니다. TM은 계정 해금이 아니라 현재 Run 동안 반복 사용 가능한 소유권입니다. 도구는 기존 가방, 장비는 기존 트레이너 장비, 알 티켓은 기존 영구 상점 지급/부화 경로를 사용합니다. 10층 상점에 영양제를 복원하지 않습니다.

상품·이름·종류·수량·재화·가격·실제 effect·구매 여부와 한도를 `hidden_shop_events.snapshot_json`에 저장합니다. 구매 요청의 상품 ID로 조회하며 차감·지급·구매 상태를 하나의 트랜잭션에서 커밋합니다. 같은 상품 재요청은 재지급/재차감하지 않습니다. [전체 풀·중복 처리·조정 위치](../engineering/HIDDEN_SHOP.md)를 참고하세요.

| 적용 대상 | 이벤트 | 현재 동작 |
|---|---|---|
| 새 이벤트 활성 런(v2) | 미스터리 상자 | 열기 / 지나가기. 아래 테스트용 결과표에서 한 번 추첨하고 공통 Reward Popup으로 확인 |
| 기존 이벤트 활성 런(v1) | 길에서 발견한 상자 | 기존 80%로 150코인, 20%로 알 뽑기권 1장. 선택 대기 상태와 이미 지급한 결과도 그대로 복구 |
| v1·v2 공통 | 브리더의 응원 | 선물 받기 / 지나가기. 받으면 알 뽑기권 1장 |
| v1·v2 공통 | 여행 상인의 제안 | 300코인으로 구매 / 지나가기. 알 뽑기권 1장, 잔액 부족 시 차감·지급 없이 재선택 |

### 미스터리 상자 초기 테스트값

아래는 **최종 밸런스가 아닌 초기 테스트값**입니다. 확률·보상·손실률은 `src/data/run-events.ts`의 `mysteryChestResults`에 모았습니다. 컴포넌트에는 하드코딩하지 않습니다.

| 계열 | 결과 | 전체 상자 기준 확률 | 적용 내용 |
|---|---|---|---|
| 꽝·손해: 합계 50% | 빈 상자 | 25% | 아무것도 얻지 못함 |
| 꽝·손해: 합계 50% | 함정 | 25% | 선택 확정 시 보유 타워 코인의 15% 손실. 소수점 버림 |
| 좋은 보상: 합계 30% | 코인 | 15% | 300 타워 코인 |
| 좋은 보상: 합계 30% | 알 티켓 | 15% | 공통 알 뽑기권 1장 |
| 매우 좋은 보상: 합계 20% | 보물 | 10% | 1,000 타워 코인 + 공통 알 뽑기권 1장 |
| 매우 좋은 보상: 합계 20% | 티켓 묶음 | 10% | 공통 알 뽑기권 3장 |

손실은 서버가 실제 잔액으로 계산해 잔액 이하로 제한하고 지갑을 음수로 만들지 않습니다. 예를 들어 101코인이면 15코인, 1코인·0코인이면 0코인을 잃습니다. UI는 비율과 실제 손실 코인을 함께 표시합니다. 코인 손실은 현재 지갑만 줄이며, 누적 획득 코인 표시는 상점 지출과 마찬가지로 총 획득량을 유지합니다.

### 진행과 공통 Reward UI

- 상자 발견 → 메시지 → `선택지 보기` → `상자를 연다 / 지나간다` → 짧은 열림 연출 → 중앙 Reward Popup → `확인` → 기존 정비·출전 준비 순서입니다. 지나가면 보상 추첨 없이 기존 진행으로 돌아갑니다.
- 하단 메시지창은 짧은 상황 안내만 담당하고 실제 결과 목록을 중복 표시하지 않습니다. 열림 연출 약 650ms 뒤 별도 중앙 팝업에서 제목·여러 결과 항목·확인을 표시합니다. 동작 감소 설정에서는 지연을 생략합니다. 코인 획득·코인 손실·알 티켓·단순 메시지를 지원하며, 빈 상자는 가짜 보상을 표시하지 않습니다.
- 팝업은 실제 modal dialog로 배경을 어둡게 표시하고 배경 클릭·키보드 조작을 막습니다. 확인에 기본 포커스·커서를 두며 Enter/Z/Space를 지원합니다. Tab은 팝업 안에서 순환하고 ESC/X·배경 클릭으로 닫지 않습니다. 모바일·작은 화면에서는 내용만 내부 스크롤하고 확인 버튼을 유지합니다. 브리더·상인과 v1 상자는 기존 문구·보상 표시·`계속하기` 흐름을 유지합니다.
- 상단 배틀 필드와 기존 상자 SVG는 그대로 보입니다. 결과 단계에는 발견 요약창을 숨기고, 꽝·손실에는 성공용 별·Glow를 표시하지 않습니다. 팝업도 neutral/loss/good/great별 테두리·강조를 구분하며 great에 짧은 반짝임을 사용합니다.
- 일반층 승리·영입 선택을 마친 뒤 만남을 추첨합니다. 5의 배수 관문·마지막 클리어·히든 보스 대기에는 추가하지 않습니다. 만난 다음 두 층은 모든 이벤트의 재등장을 막으며, 지나가도 동일합니다. 층·승리 횟수·보스 배치를 소모하지 않습니다.

### 저장·결제·호환

- DB v35에서 이벤트 규칙은 v1·v2를 구분합니다. 기존 런의 활성화 여부와 v1을 유지하고 새 이벤트 활성 런만 v2를 사용합니다.
- 서버가 상자를 열 때 결과를 한 번 추첨하고, 실제 손실·획득 항목을 포함한 `RewardResult`를 `result_json`에 저장합니다. 재접속 시 문구·항목·수량까지 같은 결과를 복원합니다.
- 결과 결정·코인 차감·모든 보상 지급·이벤트 선택과 결과 저장은 하나의 기존 트랜잭션에서 처리합니다. 한 항목이나 결과 저장이 실패하면 코인 손실·획득과 티켓 지급도 모두 롤백합니다.
- 같은 선택 재전송은 재추첨·재차감·재지급하지 않습니다. 이미 확정한 것과 다른 선택은 거절합니다. 결과 확인 전 다음 배틀 진입은 서버에서도 막습니다. `확인`은 완료 상태만 저장하며 보상을 다시 지급하지 않습니다.
- 코인은 현재 도전 지갑에, 알 뽑기권은 영구 보관함에 반영합니다. 기존 런·대기 이벤트·지급 보상·완료 기록을 마이그레이션에서 재정산하지 않습니다.

## 도전자 선택전

층을 소모하지 않는 추가 만남입니다. **후보 3명 → 선택 또는 돌아간다 → 기존 엔진 3 VS 3 → 영입 없이 Reward Popup → 추가 보상 선택/확인 → 같은 다음 층 출전 준비** 순서입니다. 돌아가면 전투·보상·패널티가 없습니다. 선택 시 직전 출전 팀을 사용하고, 처음 3명을 고르는 별도 창은 추가하지 않았습니다.

공통 NPC 20개 Sample 풀에서 **가중 랜덤 3명**을 제시합니다. Sample ID와 표시명 모두 중복되지 않으며 쉬움·보통·어려움을 한 명씩 보장하지 않습니다. 추첨한 3개 정의만 서버에 저장하고 새로고침·재접속 시 유지합니다.

포켓몬 브리더·신사·등산가·학생·연구원·베테랑·레인저·에이스 등 20개 전투 컨셉이 일반층과 같은 Sample을 사용합니다. 같은 표시 클래스의 다른 Sample은 함께 나오지 않습니다. 내부 tactic과 표시명을 분리하며 일반 NPC의 전투 스타일 설명은 숨깁니다. 특별 후보만 optional specialHint를 표시합니다.

층수는 기존 종족 풀을 결정하고 Normal/Elite/Master Rank가 IV·EV 예산·기술·도구 품질과 기믹 사용 성향을 결정합니다. 신규 후보는 층 보정·육성 배율·공통 HP 추가·무조건 Leftovers를 사용하지 않습니다. IV 31, 개별 포인트 32·합계 66을 유지합니다. 기존 저장 후보는 원래 정의와 배틀을 복구합니다.

각 후보의 Rank는 클래스별 rankWeights와 도전자 prior(50/42/8)를 곱해 정규화합니다. 반바지 소년 Master, 에이스/베테랑 Normal 등 0 가중치 Rank는 제외하며 테마 팀은 Rank가 올라가도 유지합니다. 보상은 NPC Sample과 분리한 Normal/Elite/Master Reward Profile을 사용합니다. 상세창에는 각각 **소소한 보상 / 희귀한 보상 / 특별한 보상**만 표시하며 종류·수량·내부 ID는 숨깁니다. 실제 보상은 후보 생성 시 서버가 함께 확정하고 승리·새로고침·재도전 때 다시 뽑지 않습니다. 전체 샘플의 표시명·tier·tactic·weight·minFloor, 계산식과 재현 예시는 [NPC 육성 프로필](../engineering/NPC_TRAINING.md)을 따릅니다.

### Rank별 Reward (신규 후보, snapshot v2)

| Rank | 받는 방식 | 초기 보상 풀·확률 |
|---|---|---|
| Normal | 무작위 1개 자동 지급, 선택 없음 | 300 타워 코인 70% / 공통 알 뽑기권 1장 30% |
| Elite | 희귀 보상 묶음 1개 자동 지급, 선택 없음 | 1,500코인 30% / 공통 알 뽑기권 3~5장 25% / 서로 다른 영양제 1~2종 각 1개 15% / 성장 포인트 300P 10% / 에픽 지닌 도구 랜덤 1개 8% / 중상급 기술머신 1개 12% |
| Master | 실제 후보 3개 중 1개 선택, 기본 코인 별도 지급 없음 | 알 계열 1개 + 성장 포인트 1,500P + 트레이너 장비 계열 1개 |

Elite 티켓 수량 3/4/5는 균등, 영양제 종류 수 1/2도 균등입니다. 맥스업·타우린·사포닌·리보플라빈·키토산·알칼로이드에서 중복 없이 추첨합니다. 영양제는 이번 도전 보관함에 지급하고 실제 사용 시 기존 +5 포인트, 한 포켓몬당 도전 전체 3개 한도를 검사합니다. 이전에 사용한 영양제 기록·효과도 유지합니다. 기존 층/종류 사용 기록 제약 때문에 같은 층의 같은 종류는 다음 층 준비에서 사용합니다.

**10층 단위 정비 상점의 영양제 판매·육성 탭은 제거했습니다.** 일반 지닌 도구·배틀 아이템·기술머신 상점과 포켓몬 조정은 유지합니다. 이전 영양제 구매 API도 차감·지급 없이 거절합니다. 보상 영양제·기술머신은 공통 배낭에서 사용하고 새 Elite 에픽 도구는 승리 시 도구 Pocket에 직접 등록합니다. 기존 저장 교환권은 호환 경로를 유지합니다.

새 Elite 에픽 보상은 기존 상점 epic 등급 풀 중 룰 적격·미보유 도구 하나를 서버 RNG로 snapshot하고 승리 시 Bag에 직접 지급합니다. 플레이어가 도구를 고르는 교환권을 새로 만들지 않습니다. 후보가 모두 소진되면 생성 시 1,500코인으로 확정하고, 생성 후 같은 도구를 이미 소유하게 됐어도 지급 시 1,500코인으로 대체합니다. 저장 snapshot은 재추첨하지 않으며 결과에는 실제 지급한 보상을 표시합니다. 트레이너 장비와 섞지 않습니다.

기술머신은 기존 unique/epic 풀 중 현재 Run 미보유 기술을 확정합니다. 파티 compatibility는 상품/보상 생성에서 제외하고 Bag 사용 시 검사합니다. 한 번 받으면 Run 동안 소비 없이 여러 멤버에게 가르치며 계정 해금에는 추가하지 않습니다. 전부 보유하면 1,500코인을 확정하고, 신규 snapshot의 TM을 지급 전에 이미 획득했어도 재추첨 없이 1,500코인으로 대체합니다. [공통 배낭](../engineering/BAG.md).

Master 알 후보는 **공통 알 뽑기권 10장 60% / 슈퍼레어 알 티켓 1장 35% / 이로치 알 티켓 1장 5%** 중 하나입니다. 종류가 후보 생성 때 확정되고 선택한 후보만 지급합니다. 전용 알 티켓은 영구 보관하며 기존 영구 상점의 알 뽑기 탭에서 해당 종류로 1개 무료 부화합니다. 기존 알 풀·등급·이로치·수집 규칙은 그대로 사용합니다. 공통 뽑기권은 기존 공통 알 기계용이며 별도의 중복 재화를 만들지 않았습니다.

Master 장비 후보는 현재 룰에서 사용할 수 있는 미보유 **다이맥스밴드 / 테라스탈오브** 중 하나를 서버가 확정하고 선택 시 기존 Trainer Equipment에 바로 지급합니다. 획득 사이 이미 보유했다면 1,500P로 대체합니다. 둘 다 보유했거나 현재 룰에 해당하는 장비가 없으면 후보 생성 시 **장비 대체 보상 5,000코인**을 고정합니다. 이때도 알·영구재화·코인으로 가치 축이 겹치지 않습니다.

금액·가중치·대체값은 `src/data/challenger-rewards.ts`, 실제 도구/TM 풀은 기존 rarity에서 유도합니다. 성장 포인트는 기존 영구 성장 재화이며 IV·성격·특성 전용 교환권을 만들지 않았습니다. 수치는 초기 테스트값입니다. 일반 전투/소모품·TM 가격(300/600~975코인), 일반 알 200P, 리롤/재도전 500~1,500P를 기준으로 정했으며 후속 경제 조정 대상입니다.

후보 3명의 Sample·Rank·실제 육성 프로필·팀·기믹·시드·보상을 이벤트 발생 때 서버에 저장하고, 선택한 상대·패킹한 팀·시드·행동 로그·보상 결과를 복구합니다. 승리 기본 보상은 한 번 지급하며, 미선택 추가 보상이 있으면 UI와 서버 모두 완료·다음 층 진입을 막습니다. 추가 보상은 서버 저장 정의에서 ID로만 찾아 지급하고 선택 상태와 같은 트랜잭션으로 커밋합니다. 같은 ID 재요청은 재지급하지 않고 다른 ID는 거절합니다.

패배는 기존 lost·영구 업그레이드 재도전 횟수 정책을 그대로 사용합니다. 재도전은 정비·출전 준비 후 **같은 도전자 팀·시드**로 시작하며 보상은 승리해야 받습니다. 무료 후보 재선택 정책은 추가하지 않았습니다. 이벤트 승리는 일반층 승리 횟수·성장 정산 횟수에 더하지 않고 이벤트 코인 획득량만 별도로 합산합니다.

하단 메시지창에서 후보 3명과 돌아가기를 선택하고 상세창은 한 명만 표시합니다. PC는 좌측, 모바일은 중앙에 표시합니다. 1/2/3은 미리보기, Z/Enter 또는 도전한다는 전투 확정, ↑↓는 이동, 4/X는 돌아가기입니다. 이름 hover/click/터치로 확인할 수 있으며 일반 battleStyle 설명은 숨기고 특별 후보의 specialHint만 표시합니다. [UI 구조·조작·검증](../engineering/CHALLENGER_SELECTION_UI.md)을 참고합니다. DB v39는 보상 보관함·사용 영수증·종류별 보상 알 티켓 테이블만 추가합니다. 기존 도전자 snapshot의 300코인·700코인+티켓·과거 선택 보상은 원래대로 지급하고 새 프로필을 소급 적용하지 않습니다. 신규 후보에만 rewardSnapshotVersion=2를 기록합니다. 보상 난수는 Sample/Rank/팀 난수와 분리해 NPC 구성을 바꾸지 않습니다.

## 현재 구현과 남은 콘텐츠 구분

| 대상 | 현재 상태 | 남은 작업 |
|---|---|---|
| Raid | 한카리아스/뮤츠 단계 전투·기본 모습 영입·특별 보상·snapshot 복구 | 보스·패턴·보상 다양화, 발생 시점/빈도·가치 |
| 로켓단 캠페인 | 도입·단서·간부·비주기 연계와 저장·보상 | 다른 조직 테마/NPC/보스/보상 필요성 검토 |
| 순간이동·히든보스 | 구간별 포탈, 조건부 챕터 완료 확정 전투 | 장기 진행·재방문·완료 직전 흐름 실사용 검증, 필요시 보스 보강 |
| 도전자·Mirror | 무작위 Sample/Rank 후보, 공통 보상/선택·강화 | 컨셉/샘플 보강·반복 체감·보상 가치 |
| 상자·선물·상인·히든상점 | 현재 선택·구매·지급·보관함 경로 구현 | 위험/보상·상품/재화별 가격·등장 빈도 |

시스템 구현은 끝났으나 콘텐츠/밸런스 검증은 끝난 것이 아니다. 옛 고정 상·중·하 도전자, 레이드 미구현, 빌런 층 교체 축소 예정이라는 설명은 현재 코드에 적용하지 않는다. Raid의 특수 전투 상태와 영입하는 기본 모습, 도전자 영입 없음도 구분한다.

## 빈도·경제 검증

전체 10%·쿨다운 2에서 시작해 전체 발생률 → 종류 weight → 내부 결과 weight를 별도로 측정한다. 현재 수치를 이번 문서 정리에서 바꾸지 않는다. 실제 100층에서 콘텐츠별 만남 횟수·체류 시간·진행 끊김·반복 피로·획득/소비/남은 코인·성장 포인트·티켓·아이템을 확인한다.

상자 위험/보상, Raid/도전자/Master/장비·히든상점의 기대 가치를 일반 전투·보스·알·성장·업그레이드와 함께 비교한다. 자동 검사·AI 시뮬레이션만으로 최종 수치를 정하지 않는다. 사람의 기본/혼합/대표 기믹 룰 100층 Run을 기준으로 확인한다. [경제·플레이 검증 순서](../current/ROADMAP.md).

## 후순위 후보

위험 선택 배틀·연승 도전·라이벌·교환 NPC는 1차 완성 필수가 아니다. 독립 상인·새 교환권·외형 보상 등 과거 예시도 확정 구현 목록으로 취급하지 않는다. 현재 성장 포인트·티켓·보상/상점으로 충족되는지 먼저 검토한다. [후순위 아이디어](EVENT_CANDIDATES.md).

회복권/부활권은 매 배틀 전 회복 흐름에 맞지 않아 제외한 방향을 유지한다. 폼 재료·별도 성장 통화·새 성격/특성/IV 교환권을 만들 계획은 현재 확정하지 않는다. 기존 개체 강화/보상 경로를 활용한다.

현재 알의 공통/전용 티켓·가격·확률은 [알 규칙](EGGS.md), 서버 저장/추가 절차는 [이벤트 개발](../engineering/EVENT_SYSTEM.md), 1차 완성의 우선순위는 [ROADMAP](../current/ROADMAP.md)이 기준이다.
